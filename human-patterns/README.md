# 人类行为、思考与差异资料

本区与[人格区](../personalities/README.md)共同使用，收录行为过程、认知、情绪动机、社会互动、文化、发展、群体描述及身体情境的公开框架。它们是不同问题的解释工具，既不全是测评标准，也没有统一的科学证据等级。

[浏览24个框架](CATALOG.md) · [机器目录](catalog.json) · [跨层组合指南](../docs/composition-guide.md)

## 选用

| 想解释的问题 | 选择方向 |
|---|---|
| 知道应该做却没有行动 | COM-B、计划行为、习惯形成；先查机会和任务条件 |
| 怎样搜索方案、判断风险、更新判断 | 有限理性、前景理论、双加工、元认知、执行功能 |
| 为什么投入、受挫后如何回应 | 自我决定、压力评价、情绪调节 |
| 为什么出现误会、群体冲突或合作 | 归因、社会认同、合作语用、社会困境 |
| 经历与环境怎样影响成长 | 社会学习、PPCT、选择—优化—补偿 |
| 不同社群的制度和规范差异 | 文化维度、紧密—宽松；先明确分析层级 |
| 祖源、外观与文化如何分别描述 | 遗传祖源与群体变异条目；不建立种族心理属性表 |
| 身体条件、信息通道、时间安排如何影响行动 | ICF、时间型；实际任务和支持条件优先 |

只加载当前问题需要的条目。构件之间可以互补，也可能来自不同理论，不能把它们相加成一个总分或视作已经验证的统一人类模型。身份、群体与身体情况未知时保持未知；不从姓名、外貌、国籍或零散发言生成真人的敏感属性。

## 层级与证据

每条沿用人格区的三个文件：`SKILL.md`、`framework.md`、`manifest.json`。`dimensions` 在此指框架构件，不意味着可施测的量表维度。`kind` 区分框架类别；新增以下元数据：

- `domain`：behavior、cognition、emotion-motivation、social、culture、development、population、embodiment。
- `analysis_level`：individual（个人过程）、group（群体比较）、multilevel（多层）。这说明解释单位，不能把群体均值回填成个人特征。
- `evidence_summary`：实际查到的研究、作者说明或官方标准，以及证据性质。
- `population_scope`：样本、场景、年代与外推限制。
- 每个来源的 `access_note`：全文、摘要、书目或搜索片段等实际访问范围；未读全文不写成全面核验。

每次应用区分四种内容：输入中已知事实、来源支持的框架解释、本库原创设计推演、仍未知的事项。作者理论、实验关联、分类标准和干预效果不是同一种证据。自检场景只检验资料是否被正确使用，不能证明心理理论或模拟人物与现实相符。

## 群体与身体差异

将遗传祖源、族群认同、社会种族分类、具体身体表型和环境经历分别记录。NHGRI说明这些描述词不能互作可靠代理；Hofstede作者站也明确VSM不是个人测验。具体依据见[群体变异](frameworks/ancestry-population-variation/framework.md)与[文化维度](frameworks/cultural-dimensions/framework.md)。

可以研究有样本和方法支撑的群体统计，也可以描述具体身体差异；不能据此生成“某族群天生更聪明、更服从、更有领导力”等个人能力规则。原创世界需要差异时，明确设定制度、训练、资源、经历、情境与人物自身的选择，并保留群体内部差异。

本次未采集真人私密材料、问卷答案或基因数据。只保存原创摘要及链接，不复制受限题本、分类库或评分密钥；具体材料条件见每条元数据。中文说明不冒充经验证的中文版量表。

## 校验

在仓库根运行 `python3 scripts/validate_library.py`。修改条目后用 `--write-catalog` 重建两个区的目录；`--self-test` 检查格式、引用与层级元数据的拒绝条件。资料仍标为 `source-grounded-draft`。
