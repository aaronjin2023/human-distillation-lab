# 把研究卡用到一张图或一页漫画

[100人目录](CATALOG.md) · [调用入口](SKILL.md) · [资料与验证边界](README.md)

以下是本库为工作台准备的创作流程，既可交给画师，也可交给图像工具。这里只保存规范与提示词，未开发工作台或验证具体绘图模型。

## 1. 固定本次任务

记录五件事：作品形式、故事中的一个变化、读者应该感到什么、必须保持的世界规则、画幅与交付用途。已有世界设定直接引用其版本，不重新发明一套。

测试题统一为：雨后的浮岛港口，一名成年修理工把迷路的机械鸟归还给一位成年旅人。两人及服饰为原创。比较不同方案时固定这个题材，避免把题材差异误认成绘画方法差异。

| 形式 | 必须明确的规格 | 本轮模板 |
|---|---|---|
| 叙事插画 | 一个视觉焦点、一个关键动作、前中后景关系 | 每张卡的单幅插画 |
| 角色设定 | 正面、右侧面、背面；同一身材服装；中性姿势 | 每张卡的角色三视图 |
| 漫画页 | 日式右到左阅读；每格一个动作；前后状态连续 | 每张卡的六格漫画 |

像素、出血、印刷色彩等按最终媒介再定；原型阶段不假设某个工具的固定参数。

## 2. 从研究到绘画决定

先区分任务模式。技法借鉴可选适合题材的兼容技法，并说明其用途；指定作品阶段目标则必须加载作者的`task-contract.json`及必读文件，逐项处理有来源的识别特征、步骤、检查点、冲突和未知。不能用任意少数通用技法代替完整方法，也不能从单图扩成全生涯风格。作者姓名可标识目标和研究来源；不假称作者亲绘或授权。

任务包记录：模式、作品阶段、媒介、输出形式、用户锁定角色／世界约束，采用／改写／舍弃特征与理由、题材替换、必要步骤和验收点。`prompts.md`只是随任务契约版本变化的起稿模板，不是完整执行单元。八维配方仍是本库原创迁移；是否纳入取决于任务，不能不加区分地全部粘贴。

正交三视图优先固定头身、体型、服装结构、中性站姿与纯净背景；只转用兼容的线、形和明暗，去除叙事构图、动作、透视夸张、背景彩条及分镜节奏。用户既定体型与颜色优先于配方，必须删改冲突段落。若舍弃识别特征导致目标覆盖下降，明确披露或缩窄目标，不继续宣称完整风格匹配。彩色插画核对用户色板；黑白漫画不自动套用封面配色，单幅图也不能证明作者的连续分镜规律。

荒木样板只对《The JOJOLands》第1卷已观察封面建立带来源的候选特征，未补写未经观察的内页规律；其余卡主要转交原始观察并等待识别项审阅。全部`image_validation`保持`not-run`，资料契约可加载不等于实际风格已还原。

## 3. 先验证缩略图和角色，再做细节

先用简单形状确定阅读顺序、主动作、视线和黑白面积。连续页按实际阅读尺寸看整页/跨页，再逐格看；对白先作为占位块参与构图，成稿后再排字。VIZ的佐佐木尚公开编辑访谈强调缩略分镜、跨页阅读、图文平衡和翻页效果，这些方法可用于此阶段。[来源：VIZ Originals Creator Newsletter, Issue 3](https://www.viz.com/blog/posts/viz-originals-creator-newsletter-issue-3)

角色先定三视图，再给关键表情和道具细节。参考页确定后，每次生成连续画面都复用它；记录服装开合、腰带位置、发型轮廓和机械鸟的翅膀结构。设定页只用形体、线条、黑白技法，不能同时套用复杂环境构图。

需要进一步系统学习时，可查官方《The Shonen Jump Guide to Making Manga》书目；本库只核读其公开介绍，未把未读书内内容写成已核方法。[官方介绍](https://www.viz.com/shonen-jump-guide-to-making-manga)

## 4. 六格示范的连续性

| 格 | 动作 | 必须保持的状态 |
|---|---|---|
| 1 | 建立雨后港口 | 码头、入口和出口方向可辨；固定人物尺寸参照 |
| 2 | 修理工发现机械鸟 | 鸟在同一处，修理工视线指向它 |
| 3 | 检查鸟翅 | 哪只手托鸟、哪只翅被检查清楚；不是额外长出手 |
| 4 | 旅人赶来 | 从已建立的入口进入；修理工仍持鸟 |
| 5 | 归还 | 鸟有明确交接路径，不同时出现在两人手里 |
| 6 | 鸟起飞，两人目送 | 交接完成，手已松开；飞行方向和视线一致 |

这6格是比较模板，不是任何作者的固定分镜法。放入实际项目时按叙事需要调整。若单次生成无法稳定控制格数或角色连续性，先拆为逐格镜头，再统一排版；这是待试验的执行方案，不能事先声称一定成功。

## 5. 实际看图才算验证

- 缩小后主动作是否仍一眼可辨？角色轮廓有没有被背景黑块吞没？
- 三视图的头身、服装、工具和左右侧是否一致？角色换视角后是否变成另一个人？
- 手、翅、关节、接触点与承重是否合理？物体有没有凭空增减？
- 页面是否按预定顺序读通？眼线、运动轴、门窗方向和道具状态能否衔接？
- 情绪是否通过表情、姿势和距离表现？删去说明文字后仍能理解事件吗？
- 有无误生成的原作角色、签名、乱码或标志？文字最终由排版层完成。

记录图像、提示词版本、输入参考和具体不合格项。一次只修一个关键问题，保留前版供比较。未看过图像或只通过JSON、链接与提示词检查时，状态保持“资料可调用，出图未验证”；不要改成风格一致性已通过。
