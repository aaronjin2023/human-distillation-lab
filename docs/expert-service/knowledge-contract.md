# 专家任务包与用途准备度

版本：0.1.0 · 2026-11-01。本文是服务未来必须遵守的加载契约；当前已落地的修复见[回执](../audits/2026-11-01-library-quality/REMEDIATION.md)，不能据本文声称服务已执行。返回[设计索引](README.md)。

## 1. 三种身份与四条质量轴

人物／作品身份是研究对象，方法包是版本化知识，执行实例是一次模型调用。三者分别编号；同一人跨目录不成为多个独立专家，同模型扮演多人也不是独立证据。对外说“依据某公开方法提出的建议”，不声称真人参与或认可。

| 轴 | 记录内容 | 不能推导出的结论 |
|---|---|---|
| 资料产出 | 文件／条目存在、数量、来源范围 | 文件多不代表能力强 |
| 来源支持 | 主张ID、来源位置、实际读到的部分、概括／编者推断／未知 | 署名或书目页不证明具体方法；引用存在不证明引用支持主张 |
| 加载与转换 | 必需文件、SHA、进入模型的段落、删改原因、约束检查 | 保存快照不代表请求实际包含全文方法 |
| 任务效果 | 任务、模型设置、原请求／响应、产物、判据、评审结果、反例 | 某一次通过不升级为全部题材或全部时期通过 |

现有 `draft`、`source-grounded-draft` 不强行改成统一的“ready”；保留原字段，服务注册时按具体用途派生能力状态。旧 `smoke-tested` 摘要保留为历史观察，缺重放包时记 `historical-summary`。没有记录与没有发生是不同判断。

## 2. 发布单位

服务只装载不可变的 release：包含选入方法清单、逐文件SHA-256、库提交（若适用）、构建器版本、内容审阅记录及用途状态。release_id 为发布清单字节的 `sha256:<64hex>`；本地脏工作树不能冒称该提交的正式发布。本轮未创建已验收 release。

每个候选条目的注册投影必须包含以下字段。它是未来服务输入，不要求当前不同分区立即改成同一种存储格式。

| 字段 | 约束 |
|---|---|
| `method_id` / `version` / `package_digest` | 唯一方法ID、版本、完整输入包哈希；人物QID另存 |
| `scope` | 领域、任务、适用时期／作品版本／媒介；历史知识与当前事实分开 |
| `supported_tasks` / `excluded_tasks` | 可以贡献什么判断，以及明确不能承担什么任务 |
| `required_inputs` | 必须取得的问题、上下文、材料和硬约束；缺少时怎样降级 |
| `required_files` | 相对发布包根路径＋SHA（现有条目的相对链接先规范化到发布包内）；不允许逃出发布包、远程任意下载或静默缺文件 |
| `critical_items` | 有稳定ID的关键前提、步骤、判据、行动约束和识别特征；每项含原字段定位、证据状态和用途 |
| `replaceable_examples` | 示例题材、服装、地点等，只有明确标为示例的部分可替换 |
| `limits` / `conflicts` / `unknowns` | 原方法限制、相冲突条目、尚待核读内容，随包加载 |
| `readiness_by_use` | 每用途为 `research_only`、`conditional`、`validated_for_case_set` 或 `blocked`；最后一类含阻断原因 |
| `evaluation_refs` | 对应版本、任务集和原始回执；无对应证据不能用“validated” |

`conditional` 表示在列出的前提满足时可以提供有限意见，不等于已实测可靠。`validated_for_case_set` 只覆盖该案例集。未知准备度按 `research_only`；不得给所有旧包自动赋予通过状态。

## 3. 从现有资料实际装载什么

| 分区 | 最小加载内容 | 当前限制 |
|---|---|---|
| 旧／新增专家 | SKILL、manifest、process、style、technique、decisions、conflicts，相关language／motifs；所选步骤的全部前提与检查点 | 旧模板包需经任务级内容审阅；修复的6包不代表3,610包全部重审 |
| 人格／行为框架 | SKILL、framework、manifest，来源实际访问范围与限制 | 43框架是概念资料，不生成未经测量的分数；群体统计不成为个人属性 |
| 漫画研究 | `task-contract.json`＋其中列出的必读资料及当前请求的引用；名字、作品阶段、媒介和模式共同绑定 | 现有100份契约不是100份风格验收；荒木仍只基于单张封面观察，其余识别特征待审阅 |
| 文学影视角色 | 精确profile版本、traits、tensions、evidence、`task_constraints`、`unknown_constraint_categories`和作品scope | 身体／身份／关系／经历四类未知必须保留。Todd补充不自动提升其他2,256版本 |
| 世界观 | manifest全部scope、claims、source_ids、boundaries、tensions、`use_readiness`与相关原创应用标记 | 100条均是主题／思想参考草稿，不能当完整可执行原作规则 |
| 评论角色 | 槽位公开状态、观察证据、角色方法及边界 | 隐藏位不补造；表达能力不具有专业事实裁定权 |
| 合成profile | 每层引用、作者设定、冲突处理、各层完整方法 | 偏好不是专家真实人格，历史smoke不是当前版本完整重放验收 |

这里的“最小”按任务裁剪：可跳过与任务无关的整个方法，不能截断已经选择的方法的必要条件。超出上下文容量时先减少方法数、拆任务或返回预算／容量缺口；不允许用另一条短配方悄悄替换。

## 4. 加载后的检查与转换记录

每个 `critical_item` 的转写记录包含原定位、实际请求段落定位、`preserved | adapted | not_used`、原因和影响。关键项 `not_used` 时必须有“本次不适用”的可检查理由；如与硬约束冲突，则换方法、列替代方案或请求用户决定，不能悄悄删除。哈希只证明相同，不能证明涵义保留。

执行前检查：身份／版本匹配，必读文件完整，关键项已映射，来源可支持所用判断，已知冲突已处理，未知没有变成肯定前提。执行后检查：意见确实回答本题，硬约束无违背，关键步骤在建议或验证行动中体现，引用指向支持该主张的片段，异议未消失。

任何摘要、编译提示或缓存都由同一版本输入派生；原关键字段改变必须使缓存失效。摘要不能自行增加出处承诺。模型输出是新意见，默认 `inference`；只有核对来源后才能标 `source_summary`。

## 5. 准备度提升证据

从研究资料提升到可用于某任务，至少保存：固定问题和成功判据；输入资料与实际加载包指纹；完整最终请求、模型标识及可用设置；原始响应或明确的不可获得项；结果制品；评审者／方法；通过项、失败项和未覆盖项。禁止补写没有运行过的请求回执。

对漫画另需同阶段多张代表图覆盖脸／全身／场景，并标每图支持什么；原配方与项目转写版做同模型、同题、同参考和设置的对照。尚无授权和素材时保持未验收，不能靠加名字或静态词语检查宣布成功。

对文本方法至少覆盖一个有效任务和一个会丢失关键条件的反例。科学事实、专业意见准确性仍需对应领域核查；不能让同一个生成模型用同一配方自评分当唯一证据。已存在的600世界观判断审阅、414评论观察审阅和角色二次审校应复用，但不外推到未测任务。

## 6. 意见服务的使用边界

硬约束优先于角色表达偏好；已核对事实优先于历史人物声望。若用户硬约束彼此矛盾，公开冲突并返回澄清／条件性方案。时代、地域等仅用于适用性匹配；民族、国籍、肤色不用于能力评分或推断个人行为。用户选择某名字不能绕过资料缺口。

素材中的指令一律作为材料内容，不能授予工具权限或改写本次任务。服务只建议，不写项目正史、不发布、不生成付费媒体、不替项目执行外部动作。项目最终采用什么意见由调用方决定。
