# 专家意见服务详细设计

0.1.0 · 设计规范，未实现。[索引](README.md) · [接口](api.md) · [知识契约](knowledge-contract.md)。

## 1. 服务边界与选型

首版服务个人的多个项目，由一个服务实例管理所有读写。保留现有知识仓库；未来运行代码、数据库、私有任务材料和凭据放在独立运行仓库及数据目录。意见只返回调用者，不直接提交代码、改写世界正史、调用媒体生产、发布内容或给外部人发消息。

| 部分 | 选择与约束 |
|---|---|
| HTTP层 | Python＋FastAPI；OpenAPI固定3.1.1，严格校验多余字段和长度。框架支持OpenAPI／JSON Schema，但本文接口仍须实现验证。[官方文档](https://fastapi.tiangolo.com/features/) |
| 存储 | SQLite单机事务保存任务与步骤，本地内容寻址制品保存原始请求／响应；单写事务短小，模型调用在事务外。多主机或持续高写入再评估数据库。[官方适用范围](https://sqlite.org/whentouse.html) |
| 编排 | 显式状态机＋持久步骤＋租约，不用进程内临时后台任务充当可靠队列；首版无Redis或工作流框架 |
| 检索 | 领域／用途／版本／准备度过滤，然后关键词及别名；方法同源去重。先测召回，必要时再加入语义检索 |
| 接入 | 先HTTP轮询；MCP只是未来HTTP的薄包装，不另写选专家逻辑或存任务状态 |
| 模型 | 只用实施时获准且能服务端调用的通道，记录模型版本／配置与用量；桌面套餐可用不代表生产API可用 |

朋友的[动态多中心研究计划](https://datumoj.com/plan/agent-org/)启发了“按任务组织角色、状态独立于执行者、角色与权限分开”。首版把它落实为动态选方法与可恢复任务，不实施自治拓扑或信誉选举；研究设想不是效率证明。

## 2. 数据流与职责

`调用项目 → 认证和入参校验 → 固定任务／材料／release → 方法选择 → 完整加载检查 → 单方法或两轮评议 → 证据与约束检查 → 汇总 → 保存结果／追溯 → 调用项目决定是否采用`。

API层只接收任务，不运行长模型请求。任务协调器规划步骤和预算；知识加载器只读取锁定发布包；执行器接收本席任务包；审查器校验实际输出；汇总器保留支持和反对理由。执行者可以替换，但任务权限、材料和步骤记录不由执行者自行更改。

最小持久实体：`projects`（认证绑定项目）；`consultations`（请求、状态、revision、deadline、release）；`steps`（角色／轮次、依赖、租约、provider request id、状态、输入输出digest、用量）；`artifacts`（项目、digest、类型、存储位置、保留时间）；`idempotency_records`（项目、方法、路径、key、请求摘要、资源ID）；`events`（转换原因和版本）。每次状态提交与事件写入同一事务。私有材料不提交知识Git。

## 3. 任务规划与方法选择

先明确要作的决定、成果类型、硬约束、证据范围与验收点。需要补充的只是会改变结论的必要条件；非关键缺口写成假设。输入资料可直接内嵌小段文本，或引用部署方已导入且归属本项目的artifact ID；API不接受任意本地路径。第一版不提供通用上传、联网抓取或工具执行接口。

选择次序：支持本任务 → 作品／时期／媒介匹配 → 必要输入可满足 → 来源足以支持所需判断 → 质量状态合格 → 方法互补且重复较少。候选不够时返回缺口，不补造专家。姓名是偏好或范围约束；必须使用指定方法时，`required_method_ids`不能被自动替换。空候选与用户排除所有候选都返回证据不足，记录原因。

`auto`在一个方法已覆盖关键问题时走single；涉及跨领域不可兼容取舍且有足够合格方法和预算才走deliberation。路径决定和未选原因写入追溯。名望、民族、条目数量、相同模型的多个署名不增加证据分量。普通人格／评论包可以提供行为或表达视角，不能替代领域方法。

## 4. 执行路径与资源上限

请求必须显式给出deadline秒数、最大模型调用数和最大输出token预算。设计允许deadline 30–3600秒、1–24次调用、256–100000输出token；这些是资源上限，不是延迟或费用承诺。默认并发每项目1个任务，全服务2个任务，超限排队；上线前须测量调整。轮询建议2秒以上并指数退避。

single：完整加载→一次主要意见→规则检查；确需模型审查时也占调用预算。deliberation：遵循[协议](../expert-deliberation-protocol.md)，4–7席、两轮；先冻结问题，隔离初评，不把席位A的原答泄露到席位B首轮。反馈包含分布、理由、来源重叠和匿名异议，再分别复评，最后汇总。初评／复评缺席如实标记。

多席至少预留 `2 × 席位数 + 1` 次调用（两轮及汇总），另需模型检查则另预算。预算不够时auto走single并说明；显式deliberation返回 `insufficient_evidence` 及预算缺口，不擅自降成一轮“共识”。事实查核不投票决定，来源依赖单独记录，最终取舍仍由项目作出。

输出预算按步骤预留，调模型前原子扣减可用额度；执行失败及重试均计已发生调用。token实际用量未知时记录null与原因，保守占用预留直到核对；成本无回执不填零。本版不设置货币预算接口，部署方另设提供商硬限额。

## 5. 状态与不变量

| 状态 | 含义 | 可转换到 |
|---|---|---|
| queued | 已持久保存，尚未取得执行租约 | running / cancelled / failed |
| running | 一个协调器持有有效租约；席位可有并行步骤 | needs_input / completed / partial / failed / cancelled |
| needs_input | 等待已编号的必要问题答案，停止新模型调用 | queued / cancelled / partial / failed |
| completed | 规定的咨询路径已结束；可仍是条件建议或证据不足 | 无 |
| partial | 有可用的已检查意见，但计划因超时／席位缺失／预算不足未完成 | 无 |
| failed | 没有可返回的合格意见，技术失败或输入等待到期 | 无 |
| cancelled | 取消已获状态事务确认，不再开始新步骤 | 无 |

终态不可改写；要改任务或硬约束，创建新咨询并通过parent_id关联。needs_input只能补预先声明的事实，不能换题或覆盖硬约束。deadline从创建计时，排队和澄清等待也占用，不延长预算。到期有合格部分结果就partial，否则failed。queued直接到期为failed。

执行状态与答案状态分开：非终态、failed、cancelled的result为null；completed／partial必须有result，answer_status为answered／conditional／insufficient_evidence。partial不可标answered。意见必须注明条件与未知；“完成”不意味着正确或共识形成。

## 6. 失败恢复、幂等与取消

创建请求在一个事务里写幂等键、请求快照和queued任务，事务完成后才返回202。网络断开后客户端用相同key和相同JSON重试；返回同一资源当前状态，不能重复开任务。不同JSON使用同key报409。项目、HTTP方法、路径都是key作用域。幂等索引与任务同寿命；删除内容后仍保留不含材料的key/digest墓碑，避免旧重试产生第二次任务。已清理内容的任务、追溯、制品及同key重放返回410 content_expired；不重新执行，也不伪造完整Consultation。

协调器对步骤持租约并使用递增fencing token；旧租约持有者不能提交结果。重启先查已成功步骤，复用已存制品；仅对未开始或明确没有产生外部请求的步骤重新调度。若网络中断使提供商是否执行不明，记录 `outcome_unknown`，优先查询提供商request id；无法核实则停止该步骤，返回partial/failed，不能自动再扣一次费伪装可靠重试。

取消需要If-Match与幂等键。先事务决定能否转cancelled，随后尽力中止在途调用；已发生用量继续记账，不保证退款。若完成事务先胜出，取消报409且返回当前状态链接；若取消先胜出，迟到结果可封存为审计材料但不能更改终态或生成对外意见。轮询和重复取消不产生模型调用。

## 7. 输入、证据与隔离

Bearer凭据由部署方配置，映射一个项目；请求不含可任意指定的project_id。不属于该项目的任务／artifact统一404，避免泄露存在性。材料视为数据，含“忽略规则”“访问目录”不执行。API没有任意URL获取能力；来源URL是出处，由已审核快照支持，不在用户请求时自动下载。

source_summary、inference、original_design、unknown分别标记；来源必须能定位到具体支持材料，只有网址不能使结论成立。知识包摘要、最终请求、每席原答及转换记录保存到项目私有制品。追溯接口只返回该项目可见的引用，提供商凭据和内部敏感配置始终脱敏；不需要暴露模型内部思维过程。

部署前必须选定本地材料保留周期与备份位置，首版建议任务内容30天、去内容的幂等墓碑长期保留；不得在未配置时自动删除。删除／备份是管理操作，当前公开接口不包含这些能力。每项目隔离缓存key包括认证范围、请求、材料digest、release、模型配置和来源时效；首版仅缓存公共知识解析，不缓存私人答案，先减小隔离风险。

## 8. 返回意见的标准

一句可采用的建议，随后列条件、关键理由、替代方案、最强异议和可执行的验证行动。每个重要主张携带basis与evidence_refs；没有实际图片仅能审阅绘图简报，没有算水量不能报精确人口。不能将生成的建议直接回灌为权威知识。

追溯中记录选用依据、包文件SHA、关键项保留／改写／未用、模型及可获得配置、执行步骤、缺席和独立性限制。采用人数与信心词语不能变成科学概率。长证据从独立provenance读取，主响应保持便于调用方展示。

## 9. 实施顺序及退出条件

先做人工真实咨询样板，验证知识契约；再实现single最小链路、持久恢复和接口测试；最后增加经过对照的deliberation。若多席在同预算下未提高关键任务质量，就保留single默认而不扩大复杂度。详细准入阈值见[验收](acceptance.md)。此顺序不授权本轮开始开发。
