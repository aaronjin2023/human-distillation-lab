# DATUMOJ 72 · 评论区角色

按用户指定的 [72.datumoj.com](https://72.datumoj.com/) 整理，保留原站编号和角色名称。2026-10-28 实际页面提供 **69 个完整角色**；70、71、72 号仅为未揭晓的隐藏位。本区目录包含 72 个位置，但只有 69 份可用资料，不补造隐藏角色的人格或台词。

这些是原站编写的评论区合成人设，含粉丝、挑剔观众、理性分析、立场交锋、路过乱入与高阶抬杠六个阵营。“怼人专家”是使用上的统称，不代表全部角色都负责反驳，也不表示拥有真实专家资质。

[浏览目录](CATALOG.md) · [加载入口](SKILL.md) · [机器目录](catalog.json) · [构建与完整性回执](verification/build.json)

## 保存内容

| 文件 | 内容 |
|---|---|
| `personas/*/SKILL.md` | 每个公开角色的独立加载卡：六个观察维度、应用步骤、虚构示例、边界与原站证据 |
| `personas/*/manifest.json`、`personas.jsonl` | 同一份结构化角色记录的单角色与汇总形式 |
| `catalog.json` | 72 个编号、69 个可用入口、3 个明确的隐藏位 |
| `source-records.jsonl` | 原站角色描述、台词、视觉设定、趣味参数及资产链接；不含图片文件 |
| `source-manifest.json` | 实际访问时间、页面哈希、提取方式、公开与隐藏编号、来源许可状态 |
| `related-roles.json` | 相似角色的区别，不因风格相近合并人物 |
| `verification/` | 既有姓名对照、构建与审查记录 |

沿用蒸笼的证据分层方法，将较短的人设压缩为一张可独立加载的卡和结构化记录，避免虚构记忆或生成空白模板。六个维度为情境性格、人设动机、注意焦点、思考方式、表达风格、互动动作。每条观察引用 `desc` 或具体 `lines.N`；证据等级 `artifact` 仅表示作者写了这一设定，不表示心理机制经实证确认。

应用步骤和例子由本库编写，标为创作应用，不冒充原站台词。每个例子提供虚构语境，现实使用仍须依据实际输入。原站的“自恋”“强迫症”等类型名属于修辞命名，不用来诊断真人；合理查证、追问定义和举反例本身也不等于恶意。

## 与已有资料组合

本区增加评论互动方式；原专家区提供领域方法，`personalities/` 与 `human-patterns/` 提供解释框架，`fictional-characters/` 保留文学影视叙事证据。按[组合指南](../docs/composition-guide.md)选取少量条目，并标注合成设定。这里的 69 个角色不计入原有 1,000 部文学影视作品，也不算作新增真实专家。

例如：“用 16 号严核实核对这段文字，再用 25 号问开开追问假设，最后用 35 号沈默然给一句克制的反对意见。”每个角色输出分别署上虚构角色名；缺少资料时指出缺口，不为了表现专业而编论文、经历或引文。

## 维护

```sh
python3 scripts/build_commentary_personas.py self-test
python3 scripts/build_commentary_personas.py build
python3 scripts/build_commentary_personas.py validate
```

在仓库根目录执行。重建使用本地冻结来源和 `intake/batch-*.output.json`，不会自动重新抓取网站；`intake/` 为本地过程文件，不计作正式交付。正式 JSONL、角色卡与来源记录可独立读取。来源内容没有被重新声明为 MIT 或 CC；本轮没有推送、发布、下载图像或修改原站。
