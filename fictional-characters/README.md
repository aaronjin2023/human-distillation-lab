# 文学与影视角色资料

截至 2026-10-28，已保存全球范围的 **1,000 部作品：文学 500 部、电影 500 部**，包括 30 部中文文学作品。共 **2,257 个角色版本、1,829 个身份节点、10,222 条有证据的维度判断**；每部实际提炼 2–4 名主要角色，符合每部 2–5 名的约定。作品入口见 [目录](CATALOG.md)，详细数量与哈希见 [构建回执](verification/build.json)。只有有来源、有提炼结果且完成证据复核的作品计入完成数。

[最终校验](verification/final-checks.json)覆盖数量、引用、身份关系、完整摘要证据与现有库兼容性；[交付说明](verification/completion.md)记录覆盖范围和已知限制。身份复核处理了当前检出的同名／别名候选；保留作品内独立身份不等于已经证明它与所有其他作品无关。

## 资料内容

| 文件 | 用途 |
|---|---|
| `works.jsonl` | 作品、入选依据、来源版本、材料限制和角色版本链接 |
| `characters.jsonl` | 各作品中的角色版本；性格、动机、价值、决策、情绪、关系、沟通、成长八个维度中有证据的部分 |
| `identities.jsonl` | 来源实体标识、系列信息或逐组核对支持的跨作品身份关联 |
| `identity-merges.jsonl` | 逐组身份合并决定、原始标识、理由和来源证据 |
| `evidence.jsonl` | 提炼与审校所用的完整摘要选摘、维度引用的句号、原页面、修订信息、归属和许可 |
| `identity-review.jsonl` | 同名／同别名候选及核对状态；候选不会触发自动合并 |
| `identity-separations.jsonl` | 已确认属于不同人物的同名组与保留理由 |
| `identity-overrides.jsonl` | 来源实体误合并时的逐作品拆分例外及证据 |
| `rejected.jsonl` | 按材料批次保留拒收记录；同一作品另换充分来源后可能获收录 |
| `works/*.md` | 可直接阅读的作品与角色卡，含每条判断的证据编号 |

一行 JSON 是一个独立记录。可按 `work_id` 连接作品、人物版本和证据，按 `identity_id` 查看同一身份的不同叙事版本；不要用角色名直接连接表。`explicit` 表示摘要直接叙述，`interpretation` 表示从具体行为作出的有限推断。未获得支持的维度放入 `unknown_dimensions`，不补人格分数、MBTI、诊断或台词。

维度判断有逐条句号引用；`tensions` 是依据完整摘要另行审校的综合笔记，没有逐项句号定位，其证据范围在 `tensions_evidence_scope` 中明确标注。完整摘要选摘随库保留并校验句数与哈希，避免只导出维度用到的句子而丢失综合笔记的依据。这些选摘仍是公开摘要，不是原作全文。

## 筛选与复核

文学来源包括 NYT 成人精装小说第一名的历史索引、全球畅销书及系列的历史销量汇编，以及中文作品的公开榜单/销量报道。文学侧以长篇小说为主，也包含少量中篇等独立叙事作品。系列中的独立作品按各自情节提炼；系列总销量不分摊给单册，也不声称后出的单册贡献了更早的销量。每部保留具体市场、日期、系列级或单书级口径；入榜不等于全球销量排名。电影使用 CMU Movie Summary Corpus 的历史票房字段作传播指标，并补充制作地区不同的作品。该字段的币种不统一，不能把数值排序称为全球票房榜；语言字段也可能只表示片中出现过某种语言。

当前电影材料来自 2012 年维基百科/Freebase 快照，影视侧具体为电影，不代表今天的影视热度，也未覆盖电视连续剧。文学材料为逐页访问的剧情和人物章节。这里进行的是**基于公开剧情与人物摘要的角色资料蒸馏**，没有宣称通读 1,000 部原作或看完所有影片。

处理顺序为：来源准入 → 冻结带编号的证据 → 模型提炼 → 另一次模型调用逐条证据审校 → 结构与引用校验 → 去重与导出。两轮可使用同一型号，不声称来自不同模型家族。审校会修正事实倒置、无据因果、把人物猜测写成事实等问题。机器审校不等于专家认证，摘要中的错误或偏向仍可能保留。真实模型和用量回执见 [批次回执](verification/model-batches.json)。

## 去重与版本

- 同一作品反复入榜、重复抓取同一来源只保留一次。不同作品的同名角色保持独立。
- 名称匹配采用 Unicode NFKC 与大小写规范化，并移除空白和标点；只生成匹配键，原始姓名仍保留。电影以来源的 Freebase **角色实体 ID** 关联身份；演员 ID、演员人口属性、角色/演员映射 ID 都不参与人格或身份推断。
- 只有唯一且明确的实体匹配才跨作品关联。缺少证据时保留作品内身份，列出同名候选，避免误合并。`identity_hint` 仅是提炼时的系列线索，不能作为已验证身份标识。
- 来源实体也可能把不同人物合并，例如《终结者2》的 T-800 与《终结者3》的 T-850。经剧情核对后，在 `identity-overrides.jsonl` 记录与原实体键绑定的拆分例外，重建时优先应用。
- 文学资料还可按来源明确关联的同一系列与完整姓名进行保守关联；单名、称号或泛称不会仅凭系列自动合并。
- 原著与改编、来源标识不同的续作角色，经比较姓名、别名、作品关系与情节后，可在 `identity-merges.jsonl` 记录明确关联。身份节点表示人物概念，不表示不同改编共享同一故事连续性；同名候选还会检查别名，但候选本身不会触发合并。
- 角色身份关联后，原著、改编、续作和重拍的资料仍独立保留；不以“较新版本”覆盖旧版本，不把性格相似的不同人物当成同一个人。

## 与现有库组合

先加载任务需要的专家方法，再从本区选择角色版本提供行为材料，必要时用 `personalities/` 或 `human-patterns/` 的框架组织观察。组合成的新人物须标注为合成设定；不要反向声称这些特征属于专家、演员或原型真人。传记电影分析的是影片塑造的人物形象。

## 重建与校验

在仓库根目录执行：

```sh
python3 scripts/distill_characters.py self-test
python3 scripts/build_characters.py self-test
python3 scripts/build_characters.py build
python3 scripts/build_characters.py validate --complete
```

`build` 仅使用 `selection.json` 指定批次中完成审校的输出；`validate --complete` 还要求目标数量达到 1,000。来源缓存、模型过程文件留在本地 `intake/`、`batches/`，不会被当作正式角色记录。可携带的数据和阅读卡保留必要引用证据，不依赖模型过程日志阅读。

## 来源许可

角色卡是对来源的选摘、翻译和改写，逐条保留归属、链接及许可；电影来源遵循 [CC BY-SA 3.0 US](https://creativecommons.org/licenses/by-sa/3.0/us/)，维基百科当前文学来源遵循页面所示的 [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)。相应衍生记录按其来源的相同许可提供。第三方内容不因放入本仓库而变为无版权材料，也没有把原著、剧本全文保存进库。

CMU 数据说明：[Movie Summary Corpus](https://www.cs.cmu.edu/~ark/personas/)；文献：David Bamman、Brendan O’Connor、Noah A. Smith，*Learning Latent Personas of Film Characters*，ACL 2013。详细采集规则见 `intake/film-sources.md`、`intake/literature-sources.md` 及中文来源说明。
