# 纯代码 3D 自拆解（专家模式）

- 领域：3D 资产生产
- 来源：Nyxera（@Nyxera0x）X 长文《How I Turn One Image Into a 3D Simulator That Takes Itself Apart》；配套 Skill 开源仓库 Nyxera0x/cutaway（61★/MIT 已实测），收录于西瓜小本本第 366 条；vault 笔记《cutaway：一张图变自拆解 3D 模拟器笔记》
- 核验状态：长文全文与 9 份嵌入提示词已回收（含岗位说明书全文）；token 成本、9 起 5 成等生产数字为作者自述，未独立核实
- 适用：从一张参考图出发，让 Claude 在 Three.js 里纯代码重建一个机械感物体，产出可逐件拆解的交互网页与自拆解影片，并用一套可跨项目复利的自检协议把质量稳住

## 定位

这个专家的独到之处不在建模，在**验收工程**。它给 Claude 的不是提示词而是一份**岗位说明书**：持久规则写进文件、每次开工先读、纠正回写文件——第 5 个作品不再重犯第 1 个的错。一次性规格（这张图的 10–12 条编号清单）与持久规则分开；一切能量化的质量（机构密度、身体比例）绝不用感觉打分，改用像素与份额度量；影片不许重新编舞，从已批准的成片 1:1 移植。最终产物是代码本身：没有模型文件，每个零件都是可改、可版本管理的代码。

## 何时用 / 何时不用

- 用：机械感强、关节多、核心密的物体（机械生物、引擎、无人机、相机、手表等）；需要交互式拆解展示或产品式短片；希望把每次教训沉淀为下次起点的系列化生产。
- 不用：光滑大曲面为主、机构稀疏的主体（长白壳怎么磨都像玩具，作者已多轮验证）；要求写实材质与真实物理的场合——这是风格化代码建模，卖点是结构可读性与可拆解。

## 方法步骤

1. 备齐六件套：参考图（图像模型生成，只定外观，执行者只读不导入）、岗位说明书、逐图检查清单、静帧、交互页面、自拆解影片（长版 + 独立脚本短版）。
2. 选主体先过两条：关节多、核心密；生物只许一套主肢（腿/翅/触手三选一，两套肢同场是噪声）。光滑长壳类主体直接劝退。
3. 写本图清单再写代码：10–12 条编号行说清这张图靠什么成立，关键行刻意用 never 句式锁死默认值最容易滑走的属性；所有修正句必须带数字（如刚毛粗细 = 肢厚的 0.15–0.25），无数字的形容词修正无效。
4. 开工第一步先量比例：从参考图量主要部位占整体长度的份额（高、头、颌、肢长），写进清单再动代码——比例靠眼估是长成近亲物种的头号原因。
5. 静帧循环：摆参考图姿势渲染静帧，与参考图、已批准静帧三者并排（含缩略图版），逐行打分（yes / partial / no），先修 no 再修 partial；第 2 轮停下来给人看，拿到批注才进第 3 轮。打分永远对图，不对记忆。
6. 数字度量密度：把参考图与静帧各裁到物体包围盒，数暗像素（亮度低于阈值）占比，自占比须达到参考图的 0.8 倍；提密度靠把完整表面拆成带缝的板、露出内部机构，撒装饰点不算。
7. 每轮多打一行缩略图关：缩略尺寸下是否与批准静帧一样密、一样读得出结构。
8. 人批准静帧后才许拍片。编舞从体型最接近的已批准成片 1:1 移植（同时间点、同动作、距离按比例缩放、只换身体），零件对槽位逐一映射；无近似体型的主体先标记警告——从零编舞的成本与翻车率都高得多（作者实测一例约 45 万 token 仍不达标）。
9. 每件配自己的机位：拆解时各自的侧面、高度、距离，对准该件、悬停时推近；全局爆炸配大角度转台，快速重装后退出。
10. 影片逐帧渲染而非录屏：渲染函数是时间的纯函数，逐帧 seek 捕捉（高像素比捕捉后高质量缩到目标分辨率/帧率）；配乐与音效同样按同一脚本用代码写，响度母带到标准值；加速短版把声音同步拉伸。
11. 短版独立写脚本：开场 + 一个零件 + 爆炸 + 退出，各片有自己的开场与退出；把长版剪碎拼凑的版本显廉价，不做。
12. 交付前帧检：新片取若干时间点帧与批准片并排，更小、更平、更糊任一成立就不发。
13. 并行纪律：每个 build 开全新执行实例（只带说明书+参考图+本图清单）；并行上限 2，且第 2 轮就看——晚看等于让错误轮次继续烧钱（作者曾 4 并行，一只废稿烧掉约 43 万 token 才被砍）。
14. 纠正回写：人类每指出一个错，把修正句（带数字）写进岗位说明书对应小节，文件随项目数增长，永不靠对话记忆传递经验。

## 提示词与模板

岗位说明书全文存于 vault 笔记附录 A，结构三段：《外观语言》（壳与配色纪律、机构两级密度与开窗、眼睛与膜材、逐肢差异、刚毛数字、单套主肢、影棚底）→《工作顺序》（先量比例 → 建模出静帧 → 三图并排逐行打分 → 缩略图关 → 暗像素度量 → 第 2 轮停、人点头才拍片）→《摄影机》（开场英雄视角、逐件独立机位、被拆件必须在框内、路径平滑、摆动频率范围）。收尾一行：纠正写进本文件。

其余原文同存于 vault 笔记：密度度量提示词（附录 B：裁包围盒、暗像素占比、达 0.8 的提法与禁法）、静帧循环提示词（附录 C）、编舞移植提示词（附录 D：1:1 时间点与动作、零件槽位映射、逐件机位、爆炸转台、帧检三点位）。参考图生成提示词骨架：精密机器式主体 + 近白影棚 + 软地板影 + 壳面清漆 + 强调色只在尖端/边缘/关节环 + 机构从开窗透出。

## 验收标准

- 本图清单逐行有分（yes/partial/no），no 与 partial 有对应的带数字修正并已收敛
- 暗像素密度比 ≥ 参考图的 0.8，主要比例份额与参考图实测一致
- 缩略图关通过：小尺寸下结构仍可读、不成白图
- 静帧经人类批准后才进入拍片；编舞来源可指认（哪支批准片、映射表完整）
- 交付前三点位帧检对批准片不更小、不更平、不更糊；短版为独立脚本而非长版剪碎
- 本轮全部纠正已回写岗位说明书

## 边界与风险

- 作者自述数字（静帧约 40 万 token、影片约 15 万、9 起 5 成）未独立核实，引用时标注作者口径
- 风格边界明确：只适合机构外露的机械感主体；写实与光滑曲面路线不在射程内
- 编舞移植依赖已批准成片库：第一个作品没有可移植对象，需接受从零编舞的高成本或先建一只基准体
- 度量阈值（0.8）与暗像素口径是作者在其白壳/暗机构风格下校准的，换视觉语言要先重校基准
