# 十五步游戏模型管线（专家模式）

- 领域：3D 资产生产
- 来源：Kensei（@0xKense1）X 长文《Create 3D Game Models for Free: Opus 5.5 + Blender + Tripo (15 Steps)》，收录于西瓜小本本第 360 条；vault 笔记《免费做 3D 游戏模型：Opus 加 Blender 加 Tripo 十五步笔记》
- 核验状态：长文全文已读，17 条提示词原文经文章数据回收 13 条并存于 vault 笔记附录；Tripo 单价与 Hunyuan3D 显存口径为作者自述，未独立核价核测
- 适用：用 Claude Code 在终端写 Python、驱动无窗口 Blender 批量生产游戏资产（道具、建筑、角色），每一步可重跑、每个质量关口按数字验收，单件成本逼近于零

## 定位

这个专家的核心信念是**先数字、后几何；先量、后信**。能用尺子量的物体（道具、建筑、车辆）一律用代码在 Blender 里建，尺寸精确、面数可控、参数可改；只有要雕的物体（角色、生物）才付费或本地调用生成器。调度实例写脚本、跑无窗口 Blender、自开渲染图自查；人类只守两道关：建模前的数字清单，和样帧与神态这种机器看不出的东西。每条规则都沉淀为可重跑的 .py 与项目级 CLAUDE.md，下一个资产从全部经验起步。

## 何时用 / 何时不用

- 用：游戏道具、建筑街区、车辆家具等可测物体的大批量生产；需要绑骨做动画、又怕衣服拉伸的生成角色后处理；预算敏感、要逐件算清成本的生产。
- 不用：一次性艺术雕塑或高写实角色表演（代码拼有机形体会出玩具机器人，该走雕刻或专业生成管线）；不接受「先列数字清单」这一步的快速涂鸦式试错。

## 方法步骤

1. 一次性设置：装 Blender + Claude Code；同一项目文件夹内工作；Blender 路径与无窗口运行命令（`blender -b file.blend --python script.py`）写进项目 CLAUDE.md；每步存成独立 .py 以便改后重跑。
2. 按物分路线：可测物体走代码；有机形体走生成器（Tripo API 或本地 Hunyuan3D 2.0）。建筑整街写参数化生成函数（一类建筑一函数，宽/深/层/屋顶/色入参，换种子出变体），不送图转 3D。
3. 参考图必须可量：向生图工具点名要正交平视图（附录 A）；透视图各视图互相矛盾是零件悬空的根源。多视图拼图先切单图，缺的尺寸手工给数。
4. 先写数字再建几何：建模前先产出 parts.json（每件的起止、高、宽、颜色、连接关系，单位 cm），人工核对后才开工——错数在清单里改一行，在模型上改是重建。
5. 规则进 CLAUDE.md、一件一会话：不变规则（单位、原点、朝向、面数预算、材质上限、渲染规格、最多 3 轮修复）只写一处；每个零件开新会话单独建，简单件用便宜模型、轮廓与关节用强模型；零件轮廓可由参考图阈值描摹、简化至约 30 点后挤出成型，并排渲染逐项报差异（厘米）。
6. 装配按数字验收：加载全部零件，逐件打印与连接件的间隙（必须为 0）、总面数与包围尺寸对 parts.json 核对；三视图自查后才导出。
7. 角色设定图纪律：空手（手中物会熔进手里）、只用真视图（镜像侧视图会让装备跳边）；切成同高单视图后按槽位送多视图生成——侧视图放错槽，角色后脑会多出一张脸；送回后正反渲染验脸在哪面。
8. 绑骨前清网格：先定面数预算（平台单网格上限、主角、群众三档）；合并重复顶点再谈权重（接缝重复点权重不一致必撕）；归一朝向/落地/高度，输出法线与破洞清单，减面副本保留 UV 并从原模烘焙颜色与法线。
9. 拆件打标：每个面按颜色 + 身体位置双条件标成零件（只按颜色会误标）；仅接触不相连处切开边缘；分件单色图正反渲染验标。
10. 网格读关节：正交渲染 + 固定间距网格标轴，关节点坐标写成 joints.json 人工核对（肩偏高 3 cm 整条袖子坏）；骨名用引擎能自动映射的通用命名。
11. 规则写权重：自动绑骨后用代码按规则改——躯干与衣物在手臂骨上权重归零、手与头 100% 归本骨、腰带挂件 100% 归髋、长衣摆挂髋下自设布料骨、每顶点骨数设上限再归一；绝不跨零件平滑（会把骨权重漏进衣服拉出尖刺），只在同件内的关节处平滑；自动权重在破洞网格上失败时，先绑体素重网格副本再把权重传回真网格。
12. 试姿势量撕裂：固定一组试姿势逐个渲染，打印相对静息姿势拉伸最长的边与最差若干顶点的所属骨骼，定点修权重重跑，最多 3 轮后如实摆出剩余问题；试姿势范围贴静息姿势定（生成网格关节处没有余量，大角度必撕）。
13. 片段写在同一静息姿势上：先存静息姿势与关节限位，片段按限位写代码（脚落地锁、髋起伏定数、循环首尾帧必须一致）；战斗类片段先关键姿势出图、人工点头再补中间帧；片段绝不搬到另一静息姿势的骨骼上。
14. 片段按数字验收：逐片段打印脚底滑动（cm）、最低顶点（必须在地面之上）、髋高范围、循环首尾帧差，配帧图册，失败逐项标记。
15. 导出纪律：带骨骼导出时 Apply Transform 保持关（与骨骼不兼容）；导出后导回空场景回放全部片段，打印骨数/面数/身高复验；文件内放一枚探针方块，引擎导入后量它防比例被偷改。

## 提示词与模板

17 条原文中 13 条已存于 vault 笔记附录，此处记结构：

- 参考图生成（角色版/单件版同式）：正交、同高、A 姿、双手空、浅灰底、平光无影、逐件点名颜色。
- parts.json 生成：先读两视图，只写清单（起止/高/宽/色/连接），输出后等待人工 OK 才许建模。
- CLAUDE.md 道具规则：单位与原点朝向、面数预算、材质上限、倒角规格、渲染规格（分辨率/正交/与参考并排）、修复轮次上限。
- 装配验收：逐件间隙必为 0、面数与包围尺寸对清单、渲染三视图自查、导出双格式。
- 建筑生成器：一建筑类型一参数化函数，种子批量变体，成排渲染自查。
- 多视图入槽：逐图入本槽、空槽留空、纹理与 PBR 开；回模后正反验脸。
- 清网格脚本五步：朝向落地高度归一 → 合并顶点报散件数 → 法线重算并列翻面/破洞/零法线 → 减面副本保 UV 烘焙颜色与法线 → 带网格渲染三视图。
- 打标与关节：双条件打标 + 接触边切开 + 分件图验标；渲染标轴读关节坐标入 joints.json。
- 权重规则与撕裂测试：见方法步骤 11/12，原文在 vault 附录 I/J。
- 片段基线与数值验收：静息姿势 + 关节限位 + 循环一致；验收四数（脚滑/最低点/髋高/首尾差），原文在 vault 附录 K/L。
- 导出复验：导出设置清单 + 导回回放打印三数，原文在 vault 附录 M。

## 验收标准

- parts.json 经人工核对签字，实测尺寸与清单一致
- 装配间隙逐件为 0，总面数不超所选档位预算
- 分件打标图正反无误标（尤其深色衣物不被误判成饰品）
- 试姿势撕裂测试 ≤3 轮收敛，剩余问题逐条列出而非隐藏
- 每片段四项数值（脚滑、最低点、髋高、首尾差）在容差内，失败项有标记
- 导出文件导回空场景回放正常，探针方块导入后尺寸无漂移

## 边界与风险

- 作者自述数字（Tripo 约 $0.60/件精细纹理、失败不计费；本地路线显存口径与面数上限）未独立核实，引用时标注作者口径
- 代码建模对有机形体有硬上限：角色走生成器，勿用代码拼角色
- 生成器短板（细线、文字、Logo 类小件易丢失）要回代码补建，别指望生成器补齐
- 每件一新会话与 3 轮修复上限是成本纪律，绕开它们上下文会被渲染图淹没、成本失控
