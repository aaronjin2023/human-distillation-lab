# 参考图先行 3D 场景迭代法（专家模式）

- 领域：3D 资产生产
- 来源：风间（@sts81998850）X 长文《如何让你的 GPT 更懂你的审美？3D 海岛实战篇》（作者亲手实作的网页 3D 海岛项目复盘），收录于西瓜小本本第 419 条；vault 笔记《参考图先行：GPT 迭代做 3D 海岛的六步工作流笔记》
- 核验状态：作者全程亲手实作、正文配图齐全（11 图 1 视频），流程可照做复述；文中未公开任何实际提示词或代码；「约 80% 的参考图还原度」为作者自述，未独立核实；工具版本口径（「Opus 5.5」「GPT」）为作者文中说法，未细说具体版本
- 适用：用 GPT / 编码 Agent 以代码直搭 3D 场景（网页 3D 等），功能能跑但审美对不齐、迭代卡在「说不清哪里不好」时

## 定位

这个专家的核心信念是**审美反馈的带宽在图不在字**。「再梦幻一点」「光影再自然一点」这类形容词对人对模型都是噪声，靠文字堆迭代轮次只会越改越偏。对策是把顺序倒过来：开工前先让生图模型把目标场景画出来，轮廓、构图、镜头、光影在 2D 图上冻结，再让编码 Agent 照图施工；迭代中文字说不清时，不继续堆形容词，而是先让模型基于当前画面生成一张优化后的美术参考图，人确认方向，再把图交给编码 Agent 当施工目标——图同时是需求文档和验收锚。风格也不靠一句形容词，拆成五项清单加分区参考图，变成每个元素都能对照的标尺。迭代的单位永远是一个视觉问题，局部问题绝不整场重做。

## 何时用 / 何时不用

- 用：代码生成的 3D 场景（Three.js 等网页 3D、程序化场景），难点在「长什么样」而非「能不能跑」；已有场景但整体观感达不到预期、文字反馈两轮无效。
- 不用：要的是可打印网格或游戏模型资产（走十五步游戏模型管线、单图拟合雕塑法）；已有精确图纸与尺寸标注的照图施工（那是数字锚定问题，不是美术锚）；纯功能性场景、无审美诉求的原型验证。

## 方法步骤

1. 参考图先行（设计冻结）：写第一行场景代码之前，先用生图模型生成一张理想场景的参考图，并在图上冻结五项——场景大小与轮廓、元素分布与空间关系、整体构图、镜头视角与展示范围、光影色彩与氛围。镜头展示范围必须在这一阶段定死：作者的第一个坑就是没定视角，场景搭完放进运行时才发现岛只露出一半。没有参考图，不开工。
2. 分析拆解再执行：把参考图交给模型，先让它分析盘点（建筑、地形、植物、环境元素清单）、拆解成可实现的 3D 模块并给出实现方案，人确认方案后才执行；不许拿到图就一次性生成全场景。第一版的验收标准只是「搭出来」——轮廓与主要元素到位即可，不以好看论成败，能搭出来只是第一步。
3. 风格拆成标准件：把美术风格定成一张五项显式清单——建筑语言、整体配色、标志性建筑、环境构成、整体氛围（作者案例：地中海圣托里尼建筑 / 蓝海白建筑配丰富花卉 / 灯塔、特色教堂、海上建筑 / 花园、码头、海岸、观景区域 / 明亮、治愈、浪漫的度假感）；再按主要分区各生成一张参考图（码头、街道、花园等），作为后续所有实现的常驻美术标尺。清单之外的风格发挥不接受。
4. 整体先搭，逐个问题迭代：先一遍实现整个场景；之后每轮只解决一个视觉问题，按序推进（如建筑外观 → 比例 → 屋顶、窗户、拱门等细节），改完截图与参考图对照、确认达标再进下一个。纪律：局部问题绝不让模型重做整个场景。丰富度不足（建筑太少、层次不够）时，扩规模、加区域放在单问题修完之后再做。
5. 美术图中介（关键招）：触发条件——某个视觉问题用文字描述两轮仍达不到效果，或自己也说不清想改成什么样。动作：停下文字迭代，让生图模型以当前场景截图为基础、针对该问题生成一张优化后的美术参考图（如新的光影效果图）；人先在图上确认方向对不对；确认后把这张图交给编码 Agent 作为施工目标照图修改；改完再截图与美术图逐项对照（光影、天空、水面、氛围）。图在此同时充当规格与验收锚。作者案例中整体光影氛围与「星空海」都是靠这一步救回来的。
6. 新元素走同回路：每个新特色元素（如花房、星空海）独立重复步骤 2–5：先有它自己的参考图或美术图，再实现，再逐个问题迭代；不许凭一段文字描述直接往场景里塞新元素。
7. 收尾对照：最终截图与最初参考图及各轮美术图并排对照，冻结五项逐项核对（轮廓、分布、构图、视角、光影氛围）；差异逐个决定接受还是再开一轮单问题迭代，不许以「整体差不多」放行。

## 提示词与模板

无固定模板（作者未公开任何实际提示词，按方法步骤执行）。可直接套用的只有两张清单的结构：

- 参考图冻结五项：轮廓 / 分布与空间关系 / 构图 / 镜头视角与展示范围 / 光影色彩氛围。
- 风格五项清单：建筑语言 / 配色 / 标志性建筑 / 环境构成 / 整体氛围，每项写成可对照的具体名词，不写形容词。

## 验收标准

- 开工前有参考图且五项已冻结，镜头展示范围在图中可判读
- 风格五项清单已成文，主要分区各有一张参考图作标尺
- 实现前有经人确认的模块拆解方案，第一版只按「搭出来」验收
- 每轮迭代只动一个视觉问题，无整场重做
- 文字两轮无效的问题已切换到美术图中介，没有继续堆形容词
- 每个新元素都有自己的参考图/美术图和一轮对照确认
- 最终成品与参考图并排对照过，差异逐个有处置（接受或再迭代）

## 边界与风险

- 单案例：方法只在一个海岛项目上完整跑过，无第二个项目复现，迁移到其他题材与引擎时效果未验证
- 「约 80% 的参考图还原度」为作者自述，未独立核实，且无量化定义，不要当指标引用
- 作者未公开任何提示词与代码，执行细节靠执行者按步骤自行补齐，复现结果会有方差
- 效果依赖所用生图模型与编码模型的能力档位；文中「Opus 5.5」「GPT」为作者口径，具体版本未细说
- 美术图中介比纯文字迭代多一步生图与人工确认，只在步骤 5 的触发条件满足时启用，不要每轮都走
