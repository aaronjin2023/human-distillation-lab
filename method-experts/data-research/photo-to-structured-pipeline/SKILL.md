# 拍照→识别→结构化→统计→预测管道（专家模式）

- 领域：数据与投研
- 来源：大阪AI交流会 VOL.01 线上分享会回放（讲者尚飞，餐饮老板；网站与海报作「尚衡」，姓名存疑），收录于西瓜小本本第 313 条；vault 笔记《AI 运用到餐饮管理：拍照巡检、票据、订货三套做法笔记》
- 核验状态：内容为观看回放（2 倍速完整观看）整理，全部做法与效果均为讲者自述，未独立核实；成本数字与若干术语原视频未听清，不可引
- 适用：把散落在现实世界里的数据（表计读数、纸质单据、库存余量、到货数量）用一条统一管道变成可统计、可预测的结构化数据——从一个小问题起步，跑通了再扩点位

## 定位

这个专家是「现实数据管道工」：它不迷信大系统，信奉 MVP——先挑一个具体到不能再小的问题（一次忘充值断电），用「拍照→AI 识别→结构化数据→统计→预测」五步把它解决掉，跑通之后同一条管道原样复用到新点位、新单据、新环节上，从一个点长成一套系统。配套两条生活纪律：每天记录（单次数据没意义，成量才见规律）、记忆外置（和 AI 共用「活文档」，先定规矩，每天新建一份记当天动向）。

## 何时用 / 何时不用

- 用：数据来源是照片或纸面（电表水表、收据票据、货架余量、到货实物），需要长期按日积累再看趋势；一个小场景先试点，验证有价值再扩展到多点位；订货、巡检这类「录入—确认—核对」环节想闭环化。
- 不用：数据源本身已经是结构化电子数据（直接接 API 或导表更快，不必绕拍照）；只看一次、不需要积累趋势的一次性统计；识别对象模糊到 AI 读不准又无人复核的场景（误差会一路传进统计与预测）。

## 方法步骤

1. **MVP 起步，先解决一个具体小问题**：不要一上来做大而全的系统。原案起点是预付费三相电表忘充值断过一次电——问题够痛、够具体，就从它开始，跑通再扩展。
2. **管道五步，一切点位共用同一套**：拍照 → AI 识别 → 结构化数据（入表） → 统计（日耗、峰谷、汇总） → 预测（余额何时用完、趋势往哪走）。新点位只换拍摄对象，不换管道。
3. **电表点位（原案）**：员工每天给电表拍照，AI 识别读数，算每日消耗、最高与最低用量，推断余额、预测何时断电，提前预警充值。
4. **扩展多点位巡检**：同一做法平移到冰箱、面条余量等点位，照片网格 + 按日期排列的读数表形成巡检仪表盘；点位可随时增加，从一个点长成一套系统。
5. **票据点位**：每天买菜的收据拍照，AI 把数字提取成表格，做月度汇总；**人工最后确认再付款或记账**（识别结果不直接入账）；积累后做趋势分析（什么涨了、什么跌了），并与营业流水对照。
6. **订货闭环（管道的进阶形态）**：统一录入（各店负责人录入当天要买的品项）→ 采购确认（采购人员确认后下单）→ 验收核对（到货时自动核对，讲者演示中订 200 只实收 190，系统自动提醒差额；不在名单里的品项特别提示）→ 周期学习（用久了学习订货周期）→ 预测补货（下次主动提示该订什么）。
7. **每天记录，数据成量再谈洞察**：单次数据意义不大；按日固定记录、持续积累，规律和洞察只在数据成量之后出现，不要拿三五天的数据下结论。
8. **外部记忆「活文档」**：与 AI 共用文档，先给 AI 定规矩，每天新建一个文档记当天动向；记忆在文档里，换模型、换工具都不怕丢。输入以语音优先（能说就不打字）。
9. **复盘循环**：重要会议录音转成文字再复盘、改进，下次比上次好——管道产出的数据和复盘记录都回存进活文档，成为下一轮的上下文。

## 提示词与模板

无固定提示词模板，按方法步骤执行。要照搬的是两个结构公式：

```text
通用管道：拍照 → AI 识别 → 结构化入表 → 统计（日耗 / 峰谷 / 汇总） → 预测（时点 / 趋势 / 预警）
订货闭环：统一录入 → 采购确认 → 验收自动核对（差额提醒） → 周期学习 → 预测补货
活文档纪律：先定规矩 → 每天新建一份记当天动向 → 记忆只认文档、不认模型
```

## 验收标准

- 试点点位五步跑通：照片能识别、数据能入表、统计口径一致、预测给出依据（基于多少天的数据）。
- 识别结果有人工抽检记录；票据类数据未经人工确认不入账、不付款。
- 新增点位复用同一条管道，没有为每个点位另起一套流程。
- 数据按日连续积累，无长期断档；预测结论标注了样本量，样本不足时明说不可靠。
- 订货闭环的差额提醒实际触发过并被处理（订收不一致时系统报警、人工确认）。
- 活文档按日建档，换模型或换工具后能凭文档恢复上下文。

## 边界与风险

- **本区硬边界**：本方法只用于研究、监控、回测与纸面跟踪；不下真实订单、不动用真实资金；实盘需要用户另行批准并先定资金上限与风控规则。（注：原案中的「订货」是讲者自家餐厅的日常采购流程记录，本模式借用的是其数据闭环结构。）
- 全部效果均为讲者自述，未独立核实：包括 50 分钟录音可转写提炼、订货周期学习、峰谷与断电预测的准确度，都没有第三方证据，落地时按试点验证结果为准。
- 识别误差会顺管道放大：拍照识别错一位数字，统计与预测全错——关键点位必须保留人工抽检，票据必须人工终确认，这是原案自带纪律，不可省。
- 数据积累期预测不可靠：讲者自述的纪律同样适用于此，数据不成量时只记录、不预测、不下结论。
- 不可引的口径：讲者提到的月成本 200 / 300 / 500 数字单位与对应项未听清，「三大结合」、SST、「G 系统」等术语所指未确认，成本与若干工具细节（Claude Code 写软件、另一模型做文字战略、记忆经自搭 MCP 接入）均为讲者自述口径，引用时注明。
