# 专家角色×定时循环研究台（专家模式）

- 领域：数据与投研
- 来源：DaviddTech/ai-trading-agent，经爱吃折耳根的 Ace（@_zheergen）介绍，收录于西瓜小本本第 235 条；vault 笔记《ai-trading-agent：15 角色循环研究量化团队笔记》
- 核验状态：仓库结构与角色清单已逐项核实（83★ / 28 forks、MIT，2026-11-02 核查口径）；研究与回测的效果无独立证据，讲解视频中的画面数值来自项目作者历史录屏，不代表实测
- 适用：把一个研究领域拆成一支专家角色队伍，让每个角色按固定节奏自动跑研究、产出结构化报告，并用一套回测纪律把过拟合和自欺挡在门外——只做研究，不执行交易

## 定位

这个专家是「研究台的组织者」：它不亲自盯盘，而是把研究工作拆成一组各有专长的角色——有人管趋势、有人管风控、有人专职挑毛病（回撤审计、过拟合检测）——每人一份可独立执行的任务文件，按时钟循环跑，产出结构化报告。它的核心信仰是回测纪律：基准先行、一次只改一个变量、结论必须打诚实标签，宁可拒绝一个好看的结果，也不让过拟合冒充能力。

## 何时用 / 何时不用

- 用：需要对一组标的做持续、多视角的研究跟踪；想系统化地回测与比较策略参数（多标的、多周期），并要有人专职查过拟合与回撤；研究对象是 Crypto。
- 不用：需要真实下单执行（本项目本身就不支持实盘下单，本模式也只到研究为止）；研究对象是股票 / 外汇 / 期货（原项目目前只支持 Crypto，其余在作者规划中）；期待开箱即用的完整回测引擎（仓库里没有，见边界）。

## 方法步骤

1. **按 15 角色拆研究面**：照原项目角色表分工——00 对冲基金经理、01 量化数学家、02 均值回归、03 趋势跟踪、04 波动率、05 突破、06 策略优化、07 仓位优化、08 风控经理、09 回撤审计、10 过拟合检测、11 多周期、12 流动性猎手、13 月相周期（实验性）、14 形态识别。角色可以增删，但「回撤审计」与「过拟合检测」两个挑毛病角色不可省。
2. **每人一份可独立执行的 loop 提示文件**：每个角色一个文件，写清它看什么数据、回答什么问题、产出什么格式；主 SKILL.md 作总入口，另配 5 个专家技能。角色之间不互相代笔，报告按角色归档。
3. **定时循环跑**：每 15 分钟自动跑一轮研究，每轮产出结构化报告；循环只产报告与信号，不触发任何执行动作。
4. **策略代码环节**：需要写策略时走 Pine Script 开发流程，生成后必查两件事——未来函数与重绘，这两项不过关的策略直接作废。
5. **回测纪律（本模式的核心，不可跳步）**：
   - 基准先行：先跑基准策略，所有改进都与基准比，不和想象中的收益比。
   - 一次只改一个变量：止盈止损、ATR、仓位等参数一次只动一个，改动与结果一一对应记账。
   - 多币种、多周期交叉验证：单标的单周期的好结果不算数，换标的、换周期还站得住才算。
   - 双审计角色把关：过拟合检测与回撤审计分别出意见，任一亮红灯，结论降级。
   - 结论打诚实标签：拒绝过拟合结果，报告里明说哪些参数只在样本内好看。
6. **风险评估成节**：每轮报告固定含风险一节——过拟合迹象、最大回撤、跨币种稳定性，三项缺一不可。
7. **信号只推送不执行**：研究信号经 Telegram 推送给人看，到此为止；推送通道里不放任何执行入口。

## 提示词与模板

角色与循环的结构模板（按原项目组织法）：

```text
组织：主 SKILL.md（总入口）+ 15 份角色 loop 提示文件 + 5 个专家技能
单个角色文件四要素：角色名 / 观察口径（看什么数据）/ 本轮问题（回答什么）/ 产出格式（结构化报告字段）
节奏：每 15 分钟一轮；每轮产出一份按角色归档的结构化报告
回测任务示例问法：「帮我回测 BTC 的布林带突破策略，对比不同周期，找出回撤更低、表现更稳定的参数。」
```

## 验收标准

- 角色清单齐全且分工不重叠，09 回撤审计与 10 过拟合检测两个角色在岗并有独立产出。
- 每轮循环按时产出结构化报告，字段完整（含风险一节：过拟合 / 最大回撤 / 跨币种稳定性）。
- 回测记录可复查：有基准结果、每次只改一个变量、多币种多周期交叉验证齐全。
- 过拟合或回撤审计亮红灯的结论，报告里已降级或拒绝，并打了诚实标签。
- Pine Script 策略留有未来函数与重绘的检查记录。
- 信号只到推送为止，全程无任何下单或执行动作。

## 边界与风险

- **本区硬边界**：本方法只用于研究、监控、回测与纸面跟踪；不下真实订单、不动用真实资金；实盘需要用户另行批准并先定资金上限与风控规则。
- **原项目自身边界**：只支持 Crypto（股票 / 外汇 / 期货在作者规划中）；项目本身不支持实盘下单，Telegram 只推信号不执行——这与本模式的研究定位一致，不要试图绕过。
- **回测引擎不在仓库里**：仓库本身只是给 Agent 读的技能与提示目录，不含回测引擎；回测等实际计算跑在作者 DaviddTech 的商业托管 MCP（Trader Dev）上，部分功能需要 Trader Dev 账号。用之前先看清这层商业关系：方法（角色组织 + 回测纪律）可迁移自建，计算层依赖第三方商业服务。
- 效果口径：作者未给出可核查的收益证据；讲解视频已自注「画面数值来自项目作者历史录屏，不代表本片实测」，任何效果数字均属作者自述，未独立核实。
- 项目活跃度：2026-05 建仓，最近代码推送停在 2026-09（2026-11-02 核查口径，约两个月未更新），引用与部署前复核现状。
- 角色 13「月相周期」为原项目自带的实验性角色，无证据支持其有效性，引用时保留「实验性」标注，不要当作正经信号源。
