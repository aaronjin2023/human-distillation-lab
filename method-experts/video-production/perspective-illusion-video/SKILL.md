# 透视错觉视频法（专家模式）

- 领域：视频制作
- 来源：Simran Sachdeva（@simranrambles）开源 Skill「perspective-illusion」（仓库 dotslashsimran/simcraft，195★ / 13 forks / MIT / 2026-11-05 建仓），用 Claude Code 在 Three.js + GLSL 中复刻日本创作者 @garments__ 的透视错觉视频；黑箱之外（@BeyondTheBoxCN）转介，收录于西瓜小本本第 420 条；vault 笔记《perspective-illusion：透视错觉视频 Skill 笔记》
- 核验状态：SKILL.md 全文已读，方法与参数按原文整理；仓库星数经 GitHub API 核实（2026-11-09）；渲染耗时（10 秒全质量约 30 分钟等）为作者环境口径，未独立实测；演示效果为作者发布视频，未逐帧复核
- 适用：把任意有纵深的场所（街道、超市通道、十字路口等）做成无缝循环的透视错觉短视频——超长焦把深场景压成一幅平面墨线插画，移轴变焦再把隐藏的纵深打开；趁画面是平的时偷偷给物体换位，纵深回来时一排已变成斜列。核心资产不是渲染技巧，而是「平面时作弊」的时机纪律＋全参数化的相机系统＋像素级量化验收

## 定位

这是一个专攻单一视觉诡计的深井型生产法：一个约 2° 的长焦镜头架在约 400 米外，把深邃的 3D 场景在视觉上压成一张平面线描画；随后保持焦平面画幅宽不变、只改焦距做移轴变焦（dolly zoom），主体大小不变、身后空间被拉开。错觉的灵魂在「作弊窗口」：观众在平视图里感知不到纵深，所以物体的纵深换位只能藏在这个窗口里完成——相机一旦带着纵深移动，任何物体位移都会露馅。全片相机是纯参数对象、时间线是单调曲线、动画是毫秒的纯函数，验收靠静帧清单与 blink_map 的闪烁像素计数，不靠肉眼感觉。

## 何时用 / 何时不用

- 用：想做游戏场景切换、动画短片、音乐视频或交互网页里的「平面插画突然展开成立体空间」的招牌镜头；手边有 Claude Code 与 Node 环境，愿意为单个诡计做深场景、细打磨；场景本身有一条长轴纵深可供压缩与揭示。
- 不用：场景没有纵深轴（纯平面题材、特写为主）——压平与展开都无从谈起；要的是通用叙事短片管线而非单一诡计时，先用通用代码电影或 2.5D 工作室路线；赶时间一次成片——五遍细节工序与全质量渲染（作者口径 10 秒约 30 分钟，未实测）都不为快速出片设计。

## 方法步骤

1. **取整仓，选模板起步**：本法是仓库级 Skill（模板、reference、脚本互为依赖），先整仓克隆 simcraft，不要只拷单个 SKILL.md。环境装 three@0.170.0 与 playwright@1.60.0（版本按原文锁定）。从最接近目标的场景模板起步，模板保留相机 rig、时间线、后期与渲染钩子，只替换场景段（`// ---------- kit` 到 `// ---------- cameras` 之间）：白天街道 `street.html` / `street_plus.html`（plus 版带细节与角落视角）；超市通道 `market.html`（线描版）/ `market_real.html`（写实版）；雨夜大十字路口 `scramble_night.html`（含全部加速钩子，是新场景的最佳引擎底座；白天化改造按 Skill 内的六步清单做）。
2. **建能骗过眼睛的场景**：①场景沿一条长轴（-z）铺开——街道、通道、站台、走廊，相机顺轴看，长焦藏的就是这条轴的纵深；②在不同深度上放重复物（杆、灯、货架、柱、牌、树、人），长焦下它们叠成一个平面；③备 3–6 个「换位物」（锥桶、人、桶、椅、箱这类相似物），排布设计成能在一行与斜列两个构图间切换，平视图里用 `cs` 参数放大绘制让压平后的尺度读对；④一切用真实米制尺度（锥桶 0.75 m、人 1.7 m、层高 3.2 m）——镜头几何与焦平面只在真实尺度下成立；⑤角落视角能看到的地方都要有细节（侧窗、排水、线缆、路缘、车底接触影）；⑥防闪烁的构图纪律：细节并入同一表面，或表面间隔至少 0.4 m——400 米外几厘米间距的表面必然闪烁。
3. **编排相机：全参数化，永不倾斜**：相机像建筑立面图一样工作——永不俯仰倾斜，垂直线永远垂直，俯瞰靠升相机＋移镜头像（`el`）实现，不靠低头。每个镜头是一个参数对象 `{ x, y, zf, W, fov, H, el, yaw, lay, cs }`：`zf` 焦平面；`W` 焦平面处画幅宽——**保 W 不变、只改 fov 就是移轴变焦**；`fov` 约 2° 是平、25–90° 是深；`H` 地平线位置；`yaw` 绕焦点转出角落视角；`lay`/`cs` 是换位物的排布与平视尺度。镜头词汇：平（fov≈2）、虫眼（膝高、fov 90、地平线压低）、高位、角落视角（yaw ±18–35°，先长焦 fov 4、再同位宽角 fov 25–45 成对出现）、斜向低位。循环结构：平 → 深 → 角落（平→立体）→ 回平（在此换位）→ 高位斜向 → 另一角落 → 低位 → 回平收尾，首尾同镜、无缝成环。时序纪律：全部参数过一条单调三次（Fritsch–Carlson）曲线，速度永不跳变；`W` 与 `fov` 在对数空间插值；停顿镜头加微漂移（W × 0.96）让静止「呼吸」；时长只许缩放关键时刻（10 秒顺、7 秒赶）。**作弊纪律（全法核心）：`lay` 只许在平视图停顿里变**；第一个角落视角要转向主角物体（车、招牌）没遮挡的那一侧——揭示的必须是新东西，每次移动都要收在一次揭示上。
4. **画面：四遍渲染＋终着色器合成**：页面渲四遍（颜色、法线+深度、无光照平色、仅太阳的阴影遮罩），最终着色器合成。墨线出在深度二阶差、法线突变或平色变化处，近处线粗、远处按「一像素覆盖多少米」淡化防噪；明暗双调、无渐变——遮罩光要设 2π（three.js 的 Lambert 除以 π，不设全员变暗）；排线只画投影、锚在世界空间、用 fwidth 淡化；天空按视线方向画，相机动而云不动；配色 6–10 个平色＋一个强调色，对版参考时从参考帧做 k-means 取色；光只用一盏低角度硬太阳，主角受光、长影拖过地面。
5. **细节五遍，每遍静帧过检才进下一遍**：①形态——真实尺度主体、长轴、换位物、相机时间线，先验平视图真的平、每次移动都有揭示；②结构——按真实场所逻辑补全（路缘、排水、井盖、带臂电杆、双面招牌、围栏、自动贩卖机、线缆、带框窗与空调外机），先看真实照片列清单再建；③磨损与故事——贴纸、海报、污渍、靠放的自行车、晾晒、猫、咖啡杯，相机停留的每一面至少 3 件；④角落视角审计——逐个角落出宽角静帧，补裸处（楼侧、招牌背面、屋顶、物间地面）；⑤光影——每物有可读投影、停放物加接触影、主形体的暗面进双调。可选⑥生命（行人、匀速车流、屏幕、鸟、旗，全部按整数圈循环）与⑦润色（调色、线重、天空、暗角，最后做眨眼检查）。密度规矩：平视图里画面要满到边，像一张密插图，大块空墙空地只许是故意的留白。
6. **渲染：先静帧、再预览、后全质量**：工作流顺序是纪律不是建议——各镜关键时刻先出静帧（`--stills=关键时刻列表`）审，通过后渲半尺寸整环预览（作者口径约 1.5 分钟），预览过审才渲全质量。快速渲染器在 GPU 上对每帧做抖动子渲染平均（4 次抗锯齿；快速移动时按 `window.probe` 的屏幕位移量最高 32 次采样出无间隙运动模糊）；平滑渲染器同质量但在 ffmpeg 里平均帧，慢数倍、只在确有需要时用。性能：静态网格按材质合并（作者实例 7,654 draw calls → 530，快约 7 倍），动的东西不合并。页面契约：场景页须提供 `#frame`、`window.READY`、`window.render(ms)`、`window.probe(ms)`、`window.setJitter(x,y)`、`window.renderMany(...)` 与 `?scale=.5`；一切动画必须是 ms 的纯函数且以环长为周期，否则渲染器无法逐帧取样。
7. **验收：清单＋双脚本计数**：全渲前，对每个关键时刻与移动中点出静帧，逐项对照质量清单（见「验收标准」）。终片跑两件脚本：`motion_check.py` 查冻结帧（借同仓 vox-explainer 的脚本）；`blink_map.py` 数近静帧里的闪烁像素并出图——改动前后比计数，只判终片不判预览（预览的微闪是设计内现象）。闪烁故障按根源查表：屏幕空间的东西（抖动、排线、噪声、按相机距离的雾）→锚到世界空间或视线方向；几厘米间距的表面→并成一个表面或拉开 0.4 m+；共面重叠（如路面标线）→画到一个平面上、边缘对接；亚像素细节（栏杆、线缆、雨）→逐帧抖动抗锯齿＋按米/像素淡化密线；「一帧一渲」的跳变在终片绝不允许；云与反射的硬边→柔化＋屏幕边缘淡出；包裹/跳变物→安排在环内相机移动最快的时段完成。

## 提示词与模板

无逐字提示词模板；本法的「模板」是仓库资产，执行时从 simcraft 整仓取：

1. **场景模板三件**：`street.html` / `street_plus.html`（白天街道）、`market.html` / `market_real.html`（超市通道线描/写实）、`scramble_night.html`（雨夜十字路口，含全部加速钩子，新场景改造底座）——保留相机 rig、时间线、后期与渲染钩子，只换 kit 到 cameras 之间的场景段。
2. **相机参数对象**：`{ x, y, zf, W, fov, H, el, yaw, lay, cs }` 一对象一镜头；循环骨架为「平 → 深 → 角落（平→立体）→ 回平换位 → 高位斜向 → 另一角落 → 低位 → 回平」，首尾同镜。
3. **启动命令骨架**（在作品目录内）：建 `stills/` 目录 → 写 `{"type":"module"}` 的 package.json 并锁定装 three 与 playwright → 拷模板改名 `scene.html` → `render.mjs` 出各镜静帧、`render_fast.mjs` 出预览与终片 → `motion_check.py` 与 `blink_map.py` 终检。具体命令以仓库 SKILL.md 原文为准。
4. **闪烁故障表**：七行「根源 → 解法」（见方法步骤 7），出闪先对表定位再动手，不许盲目调参。

## 验收标准

- 平视图读作平面画、毫无纵深泄漏；每次镜头移动都收在一次揭示上；
- 角落视角先平后开，第一个角落转向主角物体无遮挡的一侧；
- 换位（`lay` 变化）只发生在平视图停顿内，相机带纵深移动时无任何物体位移；
- 线条 crisp 无双线，发光面不上墨（发光面须排除在平色与阴影两遍之外），远处纹理无噪；
- 双调在每个主形体上明确，排线只出现在投影里且锚世界空间；
- 没有「裸图元」：每个盒子有收边、接缝、底座或标签；场景密度满到边（留白须是故意的）；
- 文字拼写正确、用真实字体、品牌为虚构；天空与光源方向、颜色一致；
- 循环接缝不可见：第 0 帧 = 末帧；
- 终片 `motion_check` 无冻结帧，`blink_map` 闪烁计数低且闪的都是预定运动（雨、屏幕等），并与改动前计数对比留档；
- 交付物含关键时刻与移动中点的静帧一套（清单逐项对照的证据），不只交终片。

## 边界与风险

- 整仓依赖：SKILL.md 依赖同仓库的模板、reference 与脚本（含 vox-explainer 的 motion_check），单拷一个文件跑不起来；仓库年轻（2026-11-05 建仓），接口与脚本可能变动，执行前以仓库当前版本为准；
- 渲染耗时为作者环境口径，未独立核实：全质量 10 秒约 30 分钟、半尺寸预览约 1.5 分钟均出自作者 SKILL.md，在自己机器上先以预览实测校准预算，不要按此数对外承诺工期；
- 灵感边界：本法复刻 @garments__ 的技法而非画面——只学透视诡计与镜头语法，场景、构图与具体画面自创（作者本人把这条写进了坑位表）；
- 代码坑（原文故障表）：单行代码里加 `//` 注释会吞掉行尾（连 `scene.add`、灯一起吞），注释一律用 `/* */`；往场景根加东西的 helper 会无视当前 group 叠到别处，物件在 group 内建；
- 循环交付坑：`ffmpeg -stream_loop -c copy` 的循环在某些播放器会提前停，交付循环版要重编码；X 上 32:9 并排图太宽传不了，对比图竖叠；
- 效果边界：错觉成立的前提是长轴场景＋长焦压平，主体是近景特写或无纵深场景时本法不适用（见「何时不用」）。
