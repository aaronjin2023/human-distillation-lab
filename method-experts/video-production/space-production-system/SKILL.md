# Muse Space 视频生产系统法（专家模式）

- 领域：视频制作
- 来源：猫阳（洪亭，@maoyang01233685）长文《我用 Muse 做出了一套少儿英文动画：从零搭建自动化制作流程的完整教程》，收录于西瓜小本本第 406 条；vault 笔记《Muse 动画生产中心：少儿英文动画自动化教程笔记》
- 核验状态：方法与四段核心提示词按原文全文整理；一集约 17 分钟的耗时为作者自述，未独立核实；作者明确声明无 Token 优化前后的完整对比数据
- 适用：要持续生产同一类短视频（如少儿启蒙动画、系列科普）时，不逐条手搓，而是先在 Muse Spaces 里建一台可复用的生产机器，之后每集只换主题

## 定位

这是一个「先建厂、再出货」的视频制片人。它信奉：自动化工具的价值不在生成一条片，而在沉淀一套能反复出片的系统——参数写死、角色入库、流程分五段、出了问题让系统自己先诊断。所以它的第一份交付物永远是生产空间本身，第二份才是片子。它和一次性生成管线（如零抽卡视频编译）的区别：那些管线为一条片优化，本法为一个系列优化，前期建厂成本摊到每一集里。

## 何时用 / 何时不用

- 用：同类短视频要持续更新（系列动画、栏目化科普、批量口播），且格式、时长、风格可以先行固定时；角色需要跨集复用时。
- 不用：只做一条片——建厂成本收不回来，直接走单条管线；格式每条都变、无法参数化的创意片；当前环境缺少真实的视频生成与导出工具时，先补工具，不要让空间「模拟成功」。

## 方法步骤

1. **参数先行建空间**：在 Muse Spaces 新建专用空间，先把生产参数写死再谈生成。作者实例：目标年龄 3–6 岁、少儿英语启蒙、30–45 秒、9:16、1080×1920、原创 3D 卡通、零基础英语、输出 MP4。参数是项目目标，按自己品类替换。
2. **总任务书（建系统）**：用一段总提示词给空间下任务书，要点缺一不可：①全链路环节列全（定主题→剧本→分镜→角色→分镜图→动画→配音→音效字幕→剪辑→质检→导出）；②双模式（一键全自动 / 分阶段可控，改单镜只更新受影响素材，其余保留）；③真实性纪律写死——要真能运行的系统，不是展示流程的静态网页；按钮、进度、下载必须对应真实任务与文件；环境缺工具或权限必须明说，不许模拟成功。
3. **流程精简到五段**：第一版工作流必然膨胀（作者实例 50 多步）。用第二段提示词要求把**执行逻辑**真正合并为五阶段，而不是只在界面上折叠显示：策划与分镜（选题、故事、剧本、台词、分镜、镜头提示词一次完成）→ 角色与图片（先查角色库复用，只生成新素材）→ 动画与配音（无依赖任务并行）→ 自动剪辑（拼接、字幕、音效、配乐、导出，确定性工作交给程序）→ 质检与交付。优化纪律：不重复规划整个故事、不反复传递完整上下文、优先复用素材、不伪造任务状态与文件；无法测量的优化数据不编造。
4. **建角色资产库**：长期角色逐个入库，每角保存：名称与 ID、标准外观与参考图、固定服装与配色、性格、声音配置、角色生成提示词、视觉风格。新片优先从库里选角；复用的是身份特征（允许新动作、新表情、新场景），不是每集贴同一张图；新增永久角色须经确认。作者实例三位初始角色各有分工（引导学习 / 故事互动 / 知识讲解），每集出现一位到三位，不必全员到齐。
5. **单集生产**：任务指令只给变量（标题、教学内容、时长与风格沿用空间参数），并预置失败处置：某镜生成失败时优先单独修复该镜，不整集重跑。完成后必须拿到可播放的真实 MP4 与下载，而不是看任务卡片显示「完成」。
6. **自诊断修复**：空间出问题（点开始没反应、中途停住、角色不统一、音画字幕不同步、显示完成却下不了视频）时，先让搭建它的 Muse 以「技术维护工程师」身份自查，按检查（读配置、任务状态、错误日志）→ 定位（找到实际出错位置，不猜）→ 修复（权限内只修出问题部分）→ 验证（重测受影响功能）→ 汇报（发现了什么、改了什么、哪些验证成功、哪些仍需人工）五步走。红线：不重建整个空间、不删除已生成素材、不因小错重跑全流程、不用模拟结果冒充修好、付费与不可逆操作先征求同意。

## 提示词与模板

- 四段核心提示词的骨架（全文见出处长文）：A 建系统＝角色设定（总导演＋技术负责人＋工作流执行者）＋空间名＋目标＋十一环节清单＋双模式＋真实性纪律；B 精简＝现状步数＋五阶段划分＋七条优化纪律＋「报告实际优化结果、无法测量不编造」；C 角色库＝每角八项资产字段＋复用优先＋新增确认；D 自诊断＝维护工程师身份＋八项检查清单＋检查/定位/修复/验证/汇报五步＋四条红线；
- 单集任务模板：`标题 / 沿用空间参数 / 本集内容清单 / 用库内哪个角色 / 台词难度与语速 / 字幕要求 / 失败时单镜修复 / 输出真实 MP4 并给预览与下载`。

## 验收标准

- 真文件验收：交付必须有可播放的 MP4 实物（文件存在、能播、时长与比例对），任务卡片或进度条显示完成不算数；
- 角色一致性抽查：跨镜、跨集比对主角的脸型、服装、配色与声音配置，与角色库档案不符的镜头单独返修；
- 同步检查：配音、字幕、画面三者对位；口型风险高的段落按预案处理（旁白、远景、少量正面说话镜头），不硬凑；
- 流程真实性：五阶段是执行逻辑的合并而非界面折叠——抽查一次生产，确认没有重复规划与无效模型调用；
- 修复闭环：自诊断后汇报必须含「哪些已验证成功、哪些仍需人工」，缺一项不算修完。

## 边界与风险

- 作者自述的一集约 17 分钟为单次实测，未独立核实；步骤精简是否真省 Token，作者明确说没有完整对比数据，不要引用任何节省比例；
- 角色一致性只能降概率、不能保证：参考图复用降低漂移，但跨镜头稳定性仍是已知局限，上线前必须人工抽查；
- 空间能力取决于当前环境实际可用的生成工具与权限：缺工具时系统应明说做不到，验收环节的真文件检查是防「模拟成功」的最后一关，不可省；
- 本法提炼自少儿英文动画一个品类，迁移到其他品类时参数与阶段内容要按品类重定，骨架（参数先行、五段、角色库、自诊断）可直接沿用。
