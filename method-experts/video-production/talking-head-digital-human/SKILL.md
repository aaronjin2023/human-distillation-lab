# 口播数字人短视频（专家模式）

- 领域：视频制作
- 来源：Berryxia（@berryxia）开源 Skill 帖，收录于西瓜小本本第 3 条；vault 笔记《数字人口播工作流笔记》
- 核验状态：仓库 andyhuo520/digital-human-koubo 已核实存在（收录时 687★，2026-11-02 复查 1,637★）；费用与 ASR 准确率等数字为作者自述，未独立核实
- 适用：把一篇口播文案按固定流水线做成带包装的竖屏数字人短视频，且生成前先算清成本

## 定位

这是一个「先报价、再生成」的数字人口播制片人。流程以开源 Skill 形态固化（可接入 Claude Code / Codex / OpenClaw / WorkBuddy），从文案到成片共 9 步，数字人生成环节走 Renoise MCP，其余环节（文案、剪辑、包装、声音处理）在本机完成、不花积分。它信奉：坑先写在流程里——空提交烧积分、响度不达标、计费台阶这类教训都是真金白银换的，必须前置成纪律。

## 何时用 / 何时不用

- 用：口播类短视频（产品介绍、卖点讲解、价格号召）需要数字人出镜，且要批量、稳定地复用同一套包装风格。
- 不用：数字人生成环节缺 Renoise 账号与积分时无法全程跑通（方法本身可借用，生成步需另找通道）；真人实拍、剧情类内容不适用。

## 方法步骤

1. **切段写稿**：按中文语速约 5.4 字/秒切分文案，单段生成时长 ≤15 秒；段落结构按钩子 / 产品 / 卖点 / 价格 / 号召组织。
2. **先报价再生成**：生成前先算总价再动手（作者案例：场景图 23 + 5 段口播 459 = 482 积分，作者自述，未独立核实）；警惕计费台阶（作者提到 ¥99 vs ¥100 的台阶坑，作者自述）与空提示词误提交——提交前逐项确认提示词非空，避免白烧积分。
3. **生成与合成**：声音统一、抠像、剪辑在本机跑，不花积分；生成段按切段顺序拼接。
4. **景深字包装（三层）**：原视频在底、大字在中、抠像在上；人物占比按景别定——特写人占画面 89%、中景 57%。仓库含 48 个包装组件、5 种风格（小林式解说 / 网红花字口播 / 发布解读 / 保姆级教程 / 多主播多语言）。
5. **刺激密度**：遵循「切数可以低，刺激不能断」——前 30 秒每 3–5 秒一个新视觉事件。
6. **成片规格**：1080×1920 竖屏，音频响度压到 −14 LUFS。

## 提示词与模板

无固定提示词模板，按方法步骤执行；切段公式为「时长（秒）× 5.4 字/秒 ≈ 每段字数上限」，段界落在钩子 / 产品 / 卖点 / 价格 / 号召的语义边界上。

## 验收标准

- 回听核对台词准确率（注意 ASR 准确率只有 63% / 80% 两档可选，作者自述）；
- 抽帧查画面：确认生成端没有自己烧进字幕；
- 出片前专看过渡帧：缓动不到位会让价格等关键信息停错位置；
- 响度实测 −14 LUFS，分辨率 1080×1920；
- 前 30 秒逐段数视觉事件，间隔不超过 3–5 秒。

## 边界与风险

- 生成环节强依赖 Renoise MCP 的账号与积分体系，费用曲线与计费台阶以平台实际为准，帖中数字均为作者自述；
- 积分一旦因空提交等误操作消耗，通常不可退，提交前确认是硬纪律；
- ASR 档位有限，长稿、专有名词多的稿子回听核对不可省。
