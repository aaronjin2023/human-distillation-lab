# 短片生产四级关卡专家（专家模式）

- 领域：视频制作
- 来源：Ryan（@7998l201）长文实操《Muse 实操教程：Muse 视频专家，从一句话主题到一条短片》，方法参考 Grok Bot「AI 视频专家」，收录于西瓜小本本第 297 条；vault 笔记《Muse 视频专家：一句话主题做短片实操笔记》
- 核验状态：文中数字为作者一次实跑自述（附 ffprobe 验参口径），外部不可核；方法步骤与提示词原文完整存于 vault 笔记
- 适用：从一句话主题正向生产一条短片（口播/科普类为佳），把返工拦在最便宜的环节，用机器验收代替「生成成功」的错觉

## 定位

这个专家的核心纪律是**返工前移**：视频是最贵、最不可控的一步，所以先用文字把片子定死，再逐级验收——每一级都可验，漂移只允许在最便宜的那一级被抓住和重做。它不以「生成成功」为交付标准：成片要过参数验真（ffprobe）和抽帧验看，收尾要如实列缺口清单，先划清「核心版验证」与「发布级」的边界再交付。

## 何时用 / 何时不用

- 用：一句话主题 → 一条短片的原创正向生产（作者实跑主题为 30 秒竖屏口播「讲清什么是网页哨兵」）；镜头数少、需要逐镜可控、要留验收证据的短片任务。
- 不用：照参考片逆向复刻（那是复刻提示词的活）；长片、多集连续剧（逐镜人工验收的成本结构不同，应走资产库前置的漫剧/短剧流水线）。

## 方法步骤

1. 关卡一·文字先行定稿：先写口播稿 + 五列分镜表，逐句对齐，不要一上来就生成视频。口播口径：中文约 3.5–4 字/秒，110 字 ≈ 28–31 秒，按目标时长反推字数。首步提示词必须明说「先别生成任何图和视频」，并先钉全片风格（作者实例：扁平矢量、蓝橙配色、无文字）。
2. 关卡二·静图逐张验收：按分镜逐张（可并行）生成静图，但验收必须一张张来，查三项——切题度 / 风格一致 / 角色一致性。漂移在这一级拦住：作者实跑中镜头 3 要求「同一只机器人哨兵安静坐着」，出图变成毛茸茸的白色小生灵、机器人没出镜，就是在看图环节被抓住的（作者自述，未独立核实）。省额度可以不重做，但发布级必须重生，没有例外。
3. 关卡三·图生视频留余量：拿验收过的静图做图生视频，两笔账先算清——①时长不精确：提示词写「约 8 秒」，实际返回恰好 10.000 秒顶格（作者自述，未独立核实），下单按上限留余量；②降清是常态：静图约 1152×2048 → 成片 704×1248（作者自述，未独立核实），在选材阶段就要计入，别等成片才发现清晰度不够。
4. 关卡四·成片机器验收：不看「生成成功」，看证据——ffprobe 验参（编码/分辨率/帧率/时长/体积）+ 抽中间帧验看动画真生效，防静图贴片冒充视频。作者实例成片参数：H.264、704×1248、24 fps、10.000 秒、约 3.0 MB（作者自述，未独立核实）。
5. 证据纪律（贯穿全程）：调用次数、成片参数、缺口清单全写明。缺口如实列——作者实例列了五处：只动态化了镜头 1（其余只有静图）、配音未合成、镜头 3 角色漂移、成片清晰度低于静图、时长顶格；并明确本轮定性为「核心版/片头段验证」，不冒充完整成片。另注意流程小坑：图像管线落盘格式/文件名可能与脚本预写引用对不上（作者实例为 .webp 长文件名），靠改名 + 回改引用解决（作者自述）。

## 提示词与模板

### 首步提示词（原文，可照抄改主题）

> 我要做一条 30 秒竖屏口播短视频，主题是『讲清什么是网页哨兵』。先别生成任何图和视频：先给我一份约 110 字的口播稿，再拆成 3 个镜头的分镜表——每个镜头写明时间段、画面内容、对应口播、制作方式。全片风格统一：扁平矢量、蓝橙配色、无文字。

要点：明说「先别生成任何图和视频」；先给口播稿再拆分镜；风格在首步一次钉死。

### 五列分镜表（列结构）

| 列 | 内容 |
|---|---|
| 时间段 | 如 0–8 秒，与口播字数按 3.5–4 字/秒对齐 |
| 画面 | 画面内容描述 |
| 对应口播 | 逐句对应到口播稿的第几句 |
| 制作方式 | 如「AI 静图」「AI 静图 → 成片镜头素材」 |

（分镜表与口播稿全文实例存 vault 笔记。）

### 缺口清单模板（交付时必填）

逐项列：未动态化的镜头 / 未合成的配音 / 角色漂移 / 降清幅度 / 时长顶格情况 + 本轮定性（核心版验证 or 发布级）。

## 验收标准

- 关卡一：口播稿字数与目标时长按 3.5–4 字/秒对得上；分镜表五列齐全、逐句对齐；风格已在首步钉死。
- 关卡二：每张静图都单独验过切题/风格/角色一致性；漂移图有处理结论（重生 or 记录缺口），发布级不许带漂移交付。
- 关卡三：图生视频的时长按返回上限留了余量；降清幅度在选材时已计入并可接受。
- 关卡四：ffprobe 参数已实测并记录（编码/分辨率/帧率/时长/体积）；中间帧已抽看，动画真生效，不是静图贴片。
- 交付物附缺口清单和本轮定性；与小本本第 207 条三帧质检（看内容质量）互补，本法验参数真实性，组成「参数真实性＋内容质量」双层验收。

## 边界与风险

- 全部量化数字（3.5–4 字/秒、10.000 秒顶格、1152×2048→704×1248、成片 3.0 MB、约 3 分钟走完制作链）均为作者一次实跑自述，外部不可核；不同平台/模型的时长与降清行为会变，每次生产仍要实测验参，不要把这组数字当行业常数。
- 作者实跑只动态化了 1/3 镜头且未配音，属「核心版验证」样本——引用本法时不要把该实例说成完整成片案例。
- 图生视频额度往往是最紧的资源：先想清哪几个镜头值得动态化，把额度留给关键镜头。
