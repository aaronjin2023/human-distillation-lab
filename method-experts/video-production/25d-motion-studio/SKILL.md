# 2.5D 动画短片工作室法（专家模式）

- 领域：视频制作
- 来源：Dumble（@Y0urDumble）长文课《How to build a 2.5D motion studio with Opus 5.5 (Full Course)》（2026-10-28），袋鼠帝（@aikangarooking）转介，收录于西瓜小本本第 416 条；vault 笔记《2.5D 动画工作室全流程：Opus 加 Blender 复刻 2700 万播放格式笔记》
- 核验状态：方法与 20 段提示词/命令按原文全文整理；2,700 万播放及同频道其它播放量为作者自述，未独立核实；作者明确声明不知道原频道（Ricks Clips）的真实管线，本文是同格式的开源等效复刻，不是原配方；工具链本体（mcp-for-blender、Remotion、Whisper、earshot 等）为真实开源仓库；帧表节拍数字为作者自创集的起始值，非测自原片
- 适用：一个人用 Claude Code + Blender 复刻并量产「扁平 2D 角色站在 3D 打光场景里」的 65 秒竖屏动画短片——一个真人嗓音讲一个真实故事；核心不是生成技巧，而是把格式拆成可测量的合同（REFERENCE.md、分镜表、帧号节拍），再用接触表＋批评者审稿循环做量化验收

## 定位

这是一个「先量格式、再建工作室」的动画生产法。它不从写剧本开始，而是从逐帧解剖一条已验证的参考片开始：把每一刀、每镜的 2D/3D 划分、运镜、字幕卡样式全部摊成带标注的测量表，格式自此是数字而不是感觉。生产中一切修订都用帧号表达（「把命中移到 1260 帧」），一切验收都看表不看片（1 帧/秒的接触表＋360px 手机测试图）。管线跑通一集后，整条流程打包成一个 SKILL.md（cartoon-studio），第二集起一集一行命令。信念只有一条：照做能复刻的是「格式」，不是「数据」——诚实边界写在前面。

## 何时用 / 何时不用

- 用：想做历史/科普类竖屏动画短片系列（YouTube Shorts 等），手边有 Blender 与编程 Agent，想要场景质感上限高、可逐帧返工的自建管线；愿意为第一集付出建棚成本、之后按集复用。
- 不用：只想快速出一集试水、不打算做系列——建棚与三遍建景的固定成本摊不回来，先用现成 Skill 路线（如 three.js + Remotion 的代码渲染动画）更划算；题材需要真人实拍感或角色写实表演时，2D 平面角色＋置换表情的格式本身不成立。

## 方法步骤

1. **先解剖参考片（REFERENCE.md）**：用 ffmpeg 以 1–2 fps 抽帧（`ffmpeg -i reference.mp4 -vf "fps=2,scale=540:-2" frames/ref-%04d.jpg`），让 Agent 先用 ffprobe 报尺寸/帧率/时长，再看帧图产出 REFERENCE.md：每一刀的时间戳与帧号、每镜什么是 2D 什么 3D、每镜运镜（静止/推/移/摇）与方向、字幕卡样式（每卡词数、位置、何时换卡）、钩子句与反转落点。**每个值必须标 MEASURED（从帧上读出的）/ ESTIMATED（目测）/ DECISION（我方创意决定）**，不确定的写明该查哪几帧。纪律：学语法不抄内容——机位、切法、字幕可学，角色、设计、剧本、故事结构永不 1:1 复制；拆解末尾产出 5 条属于自己这一集的决定。
2. **格式写进 CLAUDE.md 当家规**：尺寸帧率死线（1080×1920、30 fps、55–70 秒，按原尺寸渲染，永不裁切或放大）；角色永远平面不上写实阴影；新镜头只落在剧本的新想法上（约每 2 秒一镜，不按计时器切）；运镜只许有理由的慢推/移，禁随机漂移与恒定环绕。故事规矩：只讲真故事，剧本每条事实断言在 sources.md 里有出处，第一行是钩子、最后一行回收钩子。画面规矩：场景一个有动机的主光＋暖色实用光源（蜡烛/窗/火把）＋景深；材质有磨损与变化，没有完美干净的东西；角色平色、粗深描边、脚下一团接触影。禁区清单：渐变底居中标题、角落标签/时间码/边框、万物淡入、每切必 whoosh、屏幕上出现 sources.md 里没有的数字或断言。审稿前置：交付给人看之前，先跑接触表自查循环（见步骤 7）。
3. **剧本：150–170 词封顶**：65 秒正常语速就这么多，这就是全部预算。选题按标题公式找（"The [object] That [did something surprising]" / "Why [thing] Always [does X]"），一次找 5 个真故事，每个给一句话梗概、为什么 12 岁和 50 岁的人都愿意转述、2 个可打开的来源。剧本结构：一句一个想法、短句、单人旁白；第 1 行是钩子并许下承诺；约 40 秒处一个反转；最后一行回收钩子。同步写 sources.md——每条事实断言一条出处，**出处由人自己再核一遍，这一步永不全权外包**。
4. **分镜表当合同**：剧本拆成分镜表，一镜一个想法、1.5–3 秒。每镜写死五项：SET（哪个 3D 场景、场景里的哪个位置）、CAMERA（景别＋运镜及理由）、CHARACTER（谁在画面里、姿势、表情表里的哪个表情）、PROP（主角道具——必须真 3D 建，不许画）、SOUND（只在有物理事件发生时才写）。**一集只建 3–5 个场景反复复用，不建 30 个**。关键节拍写帧不写秒：列全局帧号表（帧号｜时间｜事件，如推镜起止帧、嘴张开帧、球落帧、命中帧、切镜帧、字幕可读帧）。用物理常识校准节奏：球落 30 cm 约 0.25 秒＝30 fps 下 7–8 帧，慢了就飘。此后一切修订都是帧号数字，Agent 不会误读。
5. **Blender 建景三遍（BLOCK→LIGHT→DRESS）**：装 `uvx mcp-for-blender`（Blender 4.2+）让 Agent 在 Blender 内写 Python 建景；MCP 关键补两件 Python 做不到的事：look（把相机视图/多角度表/动画条给 Agent 看，它能自查不是猜）和 search_assets（拉 Poly Haven 的 CC0 HDRI 与贴图，可商用免署名）。每集 3–5 个场景，每景三遍、每遍停下来看图：Pass 1 BLOCK——灰模墙体/王座/柱子/地面，把分镜表里每个机位摆好，逐机位 look 出表；Pass 2 LIGHT——一个有动机的主光（窗）、暖色实用光（蜡烛/火把）、一张 Poly Haven HDRI 做填充，禁止三点式影棚光，3 个机位出静帧；Pass 3 DRESS——带磨损与变化的材质、旗帜/地毯/小道具，每台相机开景深、焦点落在角色站位。渲染尺寸就是 1080×1920，永不渲大再裁。**主角道具永远真 3D 先行**：故事讲的那个东西（如地动仪的罐）从不画成平面图——真实尺度、每条边倒角、凹陷处做旧，单独建好先渲 6 角度转台检查表过了，再放进场景站位。
6. **2D 角色进 3D**：先让 Agent 按部件画 SVG（头/身/臂/腿/帽子或服装，分文件、透明底），再出一张表情表（眼睛：平常/瞪大/眯起/闭眼/斜视；嘴：闭合/小张/大张/撇嘴/咧嘴；附加：汗滴、脸红），风格纪律：平色、统一粗深描边、无渐变无纹理，2 倍尺寸导出 PNG。进 Blender 用 Import Images as Planes + Emit/Shadeless 着色器（场景灯光不给角色上阴影），脚下加一团柔和接触影让角色「坐」在地板上而不是飘，表情用置换动画按节拍换。**每镜先写表演行再动手**：thought（角色心里想什么）→ anticipation（动作前先动眼，提前约 4 帧）→ action（动作落在哪个词上）→ hold（定住多少帧让表演读出来）；规矩：禁待机弹跳，每个动作先起于一个眼神，嘴型只在重读词上换。
7. **声音：自录旁白＋逐词字幕＋耳审**：旁白自己录——真人声带呼吸是这个格式最大的信任信号，也绕开声音克隆的版权问题。用 Whisper 出逐词时间戳（`whisper voice.wav --model small --word_timestamps True --output_format json`），据此在 Remotion 里搭字幕层：1–2 词一卡、切点精确落在每个词的起始时间、白粗体＋深描边、画面中下、9:16 安全区内；不要每词都弹入动画，只在重读词上。音效用 earshot（开源 MCP，让 Agent 能听音频、审查、做声）审混音：人声永远在最上、音乐压在下面；音效只落在物理事件发生的帧（球落、门砸）；whoosh 全片不超过两次；音乐在最后一帧收束。音效线索与画面事件写进同一套帧号表；**音效文件的前导静默会让命中点偏移——找到波形峰值再平移对齐帧**。
8. **审稿循环：看表不看片**：不要把完整导出看十遍。生成两张表：接触表（`ffmpeg -i out/episode.mp4 -vf "fps=1,scale=240:-1,tile=8x9"` 每秒一帧全片一图）和手机测试图（360px 宽、每 3 秒一帧）。把表交给 Agent 当**批评者不当作者**：明确「你没做这片，你是最严苛的动画导演」，按清单查——角色都坐在地板上吗（接触影）、有没有角色被打得像 3D 物体、有没有镜头超过 3 秒没有新想法、字幕在手机尺寸可读吗、屏幕上有没有 sources.md 里没有的断言；列出全部问题带时间戳，**只修最差 3 项，只重渲受影响的帧段**（`blender -b episode.blend -o //review/fix_ -s <起帧> -e <止帧> -a`，单帧用 `-f <帧号>`），再出新表复查。每次修正用四字段锁范围：WHERE（全局帧段）/ PROBLEM（错在哪，带帧号证据）/ CHANGE（只改什么，含帧号与缓动方式）/ KEEP（什么不许动：运镜、切点、字幕时机、其它镜头）。修正顺序：错/缺 → 可读性 → 时机 → 视觉细节。批准后上传前用 ffprobe 验导出：应为 1080×1920、帧率 30/1、时长与计划一致。
9. **打包成 Skill，一集一行**：循环跑通后把整条管线写成 SKILL.md（本课成品名 cartoon-studio，存 ~/.claude/skills/cartoon-studio/SKILL.md）：流水线八步（出题带出处待选 → 剧本＋sources 待批 → 分镜表 → 三遍建景每遍出表 → 主角道具 3D＋角色平面进场 → 表演行后动画 → 旁白→逐词字幕→earshot 审混音 → 接触表＋手机测试→批评者→只修最差 3→重复），硬规则三行（原尺寸渲染、断言必有出处、永不抄他频道角色/设计/剧本）。运营纪律：别先规划频道，先端到端做完一集再决定；全程分环节计时（第二集才知道第一集真实成本）；文书与成片同文件夹存（script.md、sources.md、shotlist.md、线索表、批准的导出），那个文件夹就是下一集的模板；上线后看留存曲线不看播放量——观众在哪一秒走人，下一集就改哪类镜头。

## 提示词与模板

原文 20 段提示词/命令全部逐字存于出处笔记，此处给每件的用途与骨架：

1. **参考片拆解提示词**：以格式而非内容为对象——ffprobe 先行；产出 REFERENCE.md 五项（切点表、2D/3D 划分、运镜、字幕卡、钩子与反转）；每值标 MEASURED/ESTIMATED/DECISION；末尾附「永不 1:1 复制」声明＋5 条自有决定。
2. **CLAUDE.md 家规模板**：五节——Format（尺寸/帧率/死线/切镜与运镜纪律）、Story（真故事＋sources.md＋钩子回收）、Look（动机光＋暖实用光＋材质磨损＋角色接触影）、Banned（禁区清单）、Review before I see anything（接触表自查循环前置）。
3. **选题＋剧本提示词**：标题公式出 5 题（梗概＋双年龄转述理由＋2 来源）→选中题写 150–170 词剧本（钩子行、40 秒反转、回收行）＋sources.md 逐条出处。
4. **分镜表提示词**：一镜一想法 1.5–3 秒；每镜 SET/CAMERA/CHARACTER/PROP/SOUND 五项；末尾强制「复用场景，一集 3–5 个」。
5. **帧号节拍表**：全局帧号｜时间｜事件（推镜起止与缩放量、动作帧、命中帧、切镜帧、字幕可读帧、hold 结束帧），示例数值是起始值、按本集物理校准改。
6. **三遍建景提示词**：BLOCK（灰模＋全机位摆位＋逐机位 look 表）→ LIGHT（动机主光＋暖实用光＋HDRI 填充，禁三点光，3 机位静帧）→ DRESS（磨损材质＋陈设＋全机位景深），每遍出图停等确认。
7. **主角道具提示词**：真实尺度、全边倒角、凹陷做旧 → 6 角度转台表（中性地面）→ 过检后放进场景站位。
8. **角色 SVG 部件＋表情表提示词**：部件分文件透明底；眼睛 5 型＋嘴 5 型＋汗滴/脸红；平色、统一粗描边、无渐变纹理；2 倍导出。
9. **表演行模板**：每镜四行 thought / anticipation / action / hold＋三条规矩（禁待机弹跳、动作先起于眼神、嘴型只换重读词）。
10. **字幕层提示词**（Remotion）：读 Whisper 逐词 JSON；1–2 词一卡切在词首；白粗体深描边中下安全区；只在重读词弹入；再把分镜表每个切点对齐到它所属的词。
11. **earshot 审混音提示词**：对照分镜表查四项——声压乐下、音效只在物理事件、whoosh ≤2 次、音乐末帧收束；音效线索表与画面共用帧号，命中点按波形峰值平移对帧。
12. **批评者审稿提示词**：打开接触表＋手机测试图；「你没做这片，你是最严苛的动画导演」；五项检查清单（接触影、角色误打 3D 光、超 3 秒无新想法、字幕手机可读、断言有出处）；列问题带时间戳→只修最差 3→只重渲那些秒数→出新表。
13. **四字段修订模板**：WHERE（全局帧段）/ PROBLEM（带帧号证据）/ CHANGE（只改什么，帧号＋缓动）/ KEEP（运镜、切点、字幕时机、其它镜头全不动）；改后渲关键帧静帧＋受影响段预览，查中间帧跳变，报告改动与输出文件。
14. **cartoon-studio SKILL.md 骨架**：frontmatter（name + description 写清格式与触发场景）＋ Pipeline 八步（两处「等我拍板」卡点）＋ Hard rules 三行；细节见方法步骤 9。

安装命令（照原文）：`uvx mcp-for-blender setup` 接 Blender；`npx skills add LottieFiles/motion-design-skill` 装动画原理（时序、缓动、迪士尼 12 原则）；`npx skills add remotion-dev/skills` 装组装与字幕；`pip install -U openai-whisper` 出逐词时间戳。

## 验收标准

- REFERENCE.md 每值带 MEASURED/ESTIMATED/DECISION 标注，无未标注的「实测」；
- 剧本 150–170 词、首行钩子、约 40 秒反转、末行回收；sources.md 每条断言有出处且人工复核过；
- 分镜表每镜五项齐全，场景数 ≤5，主角道具标注真 3D，关键节拍全部帧号化并经物理校准；
- 每景三遍各有 look 表留档，主角道具有 6 角度转台表；
- 每镜有表演行，角色脚下有接触影、无待机弹跳；
- 字幕 1–2 词一卡、切在词首；音效只落在物理事件帧且命中点对波形峰值；
- 审稿循环留痕：接触表＋手机测试图在档，批评者问题清单带时间戳，每轮只修最差 3 项且只重渲受影响帧段，修订单四字段齐全；
- 导出 ffprobe 验过：1080×1920、30/1、时长合计划；
- 屏幕上任何数字与断言都能在 sources.md 里找到。

## 边界与风险

- 播放量口径：参考片 2,700 万播放及同频道 13M/10M/10M 均为作者自述，未独立核实；本法承诺复刻格式，不承诺复刻数据——第一集的真实成本与效果只能自己跑完一集才知道；
- 作者明确声明不知道原频道的真实管线，本文是开源等效复刻；「Opus 5.5」为作者环境用词，执行时以当下可用模型为准，管线结构不依赖具体型号；
- 帧表节拍数字是作者自创集的起始值，非测自原片——引用与套用前按本集的物理与语速重新校准；
- 版权与平台：学语法不抄内容（角色/设计/剧本永不抄）；YouTube 变现政策打击大规模重复内容，原创单集、真故事、真人声、每集新场景是护身符；动画属明显非真实内容一般免于 AI 披露标签，但做得像实拍的要标；旁白自录同时是版权与信任的双保险，不要换成克隆声；
- 事实错误是这条线最贵的事故：评论区一个日期错误烧掉的信任比任何渲染都贵，sources.md 不是杂活；
- 工具依赖：mcp-for-blender、earshot 等为社区开源仓库，版本与可用性会变；任一组件失效时按方法步骤用等效工具重建该环并重跑审稿循环，不要跳过验收。
