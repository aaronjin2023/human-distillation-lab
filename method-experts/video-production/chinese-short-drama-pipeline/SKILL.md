# AI 中文短剧流水线专家（专家模式）

- 领域：视频制作
- 来源：红莲魔尊（@maoyang01233685）实操教程长文，收录于西瓜小本本第 176 条；vault 笔记《AI 中文短剧全流程：ChatGPT 加 Muse 加 Fish Audio 笔记》
- 核验状态：流程与三段提示词全文存于 vault 笔记，属作者实操自述；工具能力与 API 细节以各官方文档为准，未逐项独立核实
- 适用：从零做 AI 中文短剧——剧本分镜、逐镜画面、角色配音、口型处理、剪映合成全链路，核心是画面与声音分离制作、口型问题先分档再花钱

## 定位

这个专家的第一判断是「把工具拆开用」：视频工具自带中文配音不自然（像外国人学普通话、音色不对），就不让它包办——ChatGPT 负责故事、人物、剧本、对白、分镜；Muse 只负责画面；Fish Audio 负责音色与中文配音；口型同步按需才上；剪映负责后期合成。第二个判断是成本意识：口型问题先分档，能用分镜规避的绝不上口型工具，只给真正的正面说话近景花 GPU 和工夫。

## 何时用 / 何时不用

- 用：中文对白短剧、对口型与中文发音自然度有要求的 AI 短剧生产；工具链为消费级串联（剪映手工后期），适合小团队/个人完整跑通一部短剧。
- 不用：无对白的纯画面短片（分离配音的流水线是多余的）；要求全自动批量出片的场景——本流程的合成环节是剪映手工操作，不为量产设计。

## 方法步骤

1. 第一段·剧本（ChatGPT）：先别急着生成视频。先出人物设定，再完整剧本，最后逐镜头分镜。分镜硬规格：拆成 5–10 秒独立镜头，每镜必须含场景、人物外貌、动作、表情、景别、运镜、对白或旁白、建议时长；中文对白用自然口语、避免书面语；不把多个复杂动作塞进一个短镜头；每镜单独输出一份可交给画面工具的视频提示词；另整理完整角色台词表供配音用。设计角色时同步为每个角色设计独立声音特点。
2. 第二段·画面（Muse）：按分镜逐镜生成，不要一次生成整部。约束：9:16 竖屏、时长按分镜、电影级动画质感、严格保持参考人物外貌服装发型比例、按分镜的场景与景别运镜、统一光照色调、不擅自改剧情、不随意加人物物体。一致性技巧：先做人物参考图，固定服装发型五官比例，每次用同一张参考图，可用上一镜尾帧作下一镜参考，每镜生成后检查人物变化。声音纪律：优先关声或不生成对白，后期只保留画面。
3. 第三段·配音（Fish Audio）：按角色选音色——旁白求清晰稳定、主角贴年龄性格、搞笑角色求辨识度；音色名是英文不代表中文自然，务必用中文台词试听定版，并建角色音色配置文件（角色 → 音色 ID）。产出规格：每句台词独立音频、记录实际时长、旁白与对白分开、生成 SRT 字幕与音频时间轴、多角色分别管理。
4. 文件整理（合成前）：按角色与镜头编号归档——video/shot_01.mp4、audio/narration_01.mp3、audio/character_A_01.mp3、subtitles/subtitles.srt，编号对齐后才进剪映。
5. 口型三档（见「提示词与模板」）：先按档位判定每句对白的处理方式，需口型的镜头先做口型再进剪映。
6. 第四段·合成（剪映）：导入片段按剧本排序 → 导入音频对位 → 按实际音频长度调镜头时长 → 删除/静音 Muse 原声（千万别两套声音叠加）→ 加字幕、音乐、环境与动作音效 → 检查同步与衔接 → 导出。

## 提示词与模板

### 提示词一·AI 短剧编剧与分镜导演（结构要点）

要求模型：完善剧情结构（开头/发展/冲突/结尾）；设计角色外貌、服装、发型、性格与关系，并为每个角色设计独立声音特点；拆成 5–10 秒独立镜头，每镜含场景、人物外貌、动作、表情、景别、运镜、对白或旁白、建议时长；保持外貌、服装、场景、画风一致；中文对白自然口语化；不把多个复杂动作塞进一个短镜头；每镜单独输出可交付的视频提示词；另出完整角色台词表。输出次序：先人物设定，再完整剧本，最后逐镜头分镜。（全文存 vault 笔记）

### 提示词二·Muse 视频生成（约束清单）

9:16 竖屏 / 时长按分镜 / 电影级动画质感 / 严格保持参考人物外貌服装发型比例 / 按分镜场景与景别运镜 / 统一光照色调 / 不擅自改剧情 / 不随意加人物物体 / 优先关声或不生成对白。（全文存 vault 笔记）

### 提示词三·让 AI 助手接入 API 的规范范本（可迁移到任何 API 接入任务）

严格以官方文档为准核对接口、鉴权、模型、参数，不得编造 API 地址与参数；先检查运行环境（语言、依赖、FFmpeg）；实现功能清单逐项落地（本例：TTS、按角色配音色、旁白对白分开、每句独立音频、记录时长、自动整理音频、生成 SRT 与时间轴、多角色管理）；建配置文件管理映射（角色 → 音色 ID）；先测试再批量；安全条款：Key 走环境变量/安全凭证，不写进公开代码与日志，涉及付费与部署先确认，声音克隆须确保授权。（全文存 vault 笔记）

### 口型三档（判定表）

- ① 直接换声不上同步：旁白、远景、背影、无正面说话的镜头——最省，默认先按这档筛。
- ② 上 AI 口型同步工具：正面说话近景才用；工具 MuseTalk / Wav2Lip / LatentSync，流程为视频+音频 → 处理 → 再进剪映；部分工具要 GPU/云 GPU 费用，Wav2Lip 开源版商用前必须核许可证。
- ③ 从分镜规避（作者最推荐的低成本法）：旁白配动作/环境镜头、对话用正反打、背影侧脸远景、减少长正面说话镜头；真重要的对白近景再单独做口型。

### 问题速查表

发音不自然→换专门 TTS；音色不统一→固定音色配置；外貌变化→固定参考图；衔接不自然→逐镜生成查连续性；口型→同步工具或改分镜；声音重叠→静音原声；时长不一致→按音频调时间轴；API 失败→查文档/密钥/权限/参数。

## 验收标准

- 分镜表齐全：每镜 5–10 秒且八要素（场景/外貌/动作/表情/景别/运镜/对白/时长）不缺项，角色台词表单独成表。
- 画面逐镜生成、逐镜查过人物变化；全片同一参考图、服装发型比例锁定。
- 每句台词有独立音频文件且记有时长；角色音色与配置文件一致，全片不串音色。
- 每句对白已按口型三档判定并留痕：规避的镜头在分镜上能看出设计（正反打/背影/侧脸/远景）。
- 成片无双声重叠（原声已删除或静音）；镜头时长已按实际音频长度对位；字幕（SRT）与时间轴对齐。

## 边界与风险

- 流程效果为作者实操自述，未独立核实；各工具的当前能力、价格与 API 以官方文档为准，接入前按提示词三的纪律重新核对，不要沿用旧参数。
- Wav2Lip 开源版商用前必须核许可证；声音克隆必须确保授权；API Key 不得公开、不得写进代码与日志。
- 口型工具部分需要 GPU/云 GPU，会产生费用，批量前先小样测试并确认预算。
- 合成环节是剪映手工后期，是这条流水线的产能瓶颈；赶工时先砍镜头数，不要砍验收项（查人物变化、查双声、查同步）。
