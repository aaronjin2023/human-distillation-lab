# 代码图解科普片工作流（专家模式）

- 领域：视频制作
- 来源：张大宇（@Kainative）长文《一个人用 Claude Code 持续做知识视频：不靠 Seedance 的开源工作流（附实测和全套提示词）》，收录于西瓜小本本第 428 条；vault 笔记《一个人用 Claude Code 做知识视频：不用生成模型的代码渲染工作流笔记》
- 核验状态：长文全文与文中 8 段提示词原文已逐字核读；作者的开源仓库链接只在原帖评论区给出，未能取到，仓库名与「12 种画法」完整清单未核；全部时间/成本/互动数字为作者自述，未独立核实
- 适用：一个人持续做竖屏知识科普短视频：讲道理、理关系、解释一个反直觉结论，全程代码渲染（Remotion），不用视频生成模型，靠拆对标与零件复用越做越快

## 定位

这是一个「先拆爆款、再用代码把知识画出来」的科普片导演。它的核心判断是：爆款知识视频的本事不在配色与氛围，而在「让知识发生看得见的变化」——珠子落下是事件、线亮起是传递、图标暗下是被排除的样本；抄氛围抄不到解释力。所以流程的重心压在最前面两步（拆对标、定文案），画面全部交给可复用的代码零件，渲染被立下「全片最多两遍」的死规矩，人的工作只剩一件：看片，说「不对，重来」。

## 何时用 / 何时不用

- 用：选题是讲道理、做科普、梳理人物/概念关系；需要频繁改稿迭代；预算为零或不想为生成模型抽卡付费；愿意先攒零件库、追求越做越快。
- 不用：讲故事、讲历史、要电影感画面——走 2.5D 路线（见 25d-motion-studio），并准备好每期新建物件与真人配音；代码画不出又必须真实感的镜头，用视频生成模型补位即可，三者可混剪，不必单选。

## 方法步骤

0. **建工作台文件夹**：固定目录（入口说明、CLAUDE.md、工作流、积累区［爆点库/拆解模板/素材总表/零件清单/发布数据/日记模板］、输入、输出、制作记忆）；新对话按固定顺序读文件续上；每类信息只写在一个地方，别处只留一句话加指向。
1. **拆对标（完全不碰画面）**：同品类点赞最高的约 20 条逐条拆，只盯四样——①互动比例：转发/赞特别高＝观众拿它发给某个人，结尾替他把那句话说出来（作者样本 47%、32%、31%，作者自述）；收藏高＝给一屏能截图的清单；评论高＝结尾留一个具体问题。②信息差：锚必须是观众天天见的熟物（反例：苏东坡从诗词出发无人有感知，换成「东坡肉人人吃过＋『东坡』二字本不存在」立刻成立）。③心理链：被说中什么→想起谁→卸下什么→想做什么。④评论区高赞：先翻评论再定方向，防把观众要的东西给错（作者曾定「练得顺反而没进步」，高赞却全在说坚持与希望）。拆解产出《拆解总览》七项：互动比例、爆点卡（时间＋证据）、信息差（锚→反差）、心理链、评论高赞、原片漏洞（这是超过它的地方）、原句禁用清单（借手法不借原话）；每个数字标「实测/估计」。
2. **写逐拍脚本，文案在这一步定死**：钩子在前 3–5 秒，第 0 帧就有字和画面（实在不行把结尾高潮剪到最前面）；一条只讲清一个点；开场用带「你」的场景，靠只有亲历者知道的细节下潜；每个例子必须真能证明主题（反例：「学吉他长茧」只能证明手指变硬，证明不了看不见的积累会突破）；字跟音乐拍子走但不追毫秒；不做承诺（不说坚持一定成功）；屏幕数字要么有出处、要么写明示意；结尾回收开头的物件、只放一种互动。切点不写帧号，写「切在第几句的哪个字」——配音出来后用 Whisper 逐字时间自动换算，改一句配音切点与字幕全自动跟走。中文坑：识别稿必须与定稿逐字对（作者 225 字对上 202 个，如「铜珠」被听成「桐珠」），余者靠前后时间估；字幕断句手写，防「一千九/百年前」式切分。
3. **画面全是代码画的**：先分析音乐得拍点表 beats.json（BPM、第一拍、各拍时间），此后所有动画时间只从拍点表取、不手写秒数。画面先翻零件清单，能复用就复用，新零件做完补进清单。每个演示段先写六行：要证明的变化／始终不变的参照／一个点代表什么／只改变的条件／观众亲眼看到的结果／一句结论和适用条件。动作纪律：稳定参照→只改一个条件→看见结果→停住让人读；先变化、后命名；打在拍上的动作 0.15 秒内到位。大字每秒不超过 6 字、小字不超过 7 字，写完跑一遍阅读时间检查。「能模拟就别画」：讲随机游走就真跑一遍随机游走，读数从模拟里来、旁注这是模拟。色彩分工示例（作者体系）：近黑暖棕底、象牙白字、香槟金细线、暗朱红只给威胁与负面；亮度按正在发生＞发生过＞无关分档。平台安全区留白：顶部约 150px、底部 380px、右侧 140px 不放关键内容；画面不加「仅供参考」类免责小字。物理自检：动画时长从真实量推导（0.72 米自由落体 0.38 秒＝30fps 下 12 帧，音效钉在落入那一帧），每个数字标注来源（量出/目测/自定）。
4. **最多渲两遍**：文案问题在第 1–2 步解决；构图、挤字、物件可辨认，靠在每个画面事件上抽静帧拼成联系表预审；只有整体节奏、声音、黑帧闪帧等问题等第一遍全片渲染才看。几十毫秒的离拍与淡入小差不管、不返工。改片只改指定镜头、只重渲改过的那几秒，改片单写明「哪些不能动」。Remotion 整片渲染若随机丢元素两三帧，是 Chrome GPU 合成的锅：改软件渲染 `--gl=swangle --concurrency=1`，代价是慢（作者环境 128 秒片约 12 分半，作者自述），但一帧不丢。
5. **审片当导演不当作者**：让审片方打开联系表与手机尺寸测试图逐项查：一屏是否只有一个重点、字在手机上是否读得清、有没有超过 3 秒没有新东西的镜头、屏幕数字有无出处、结尾有无回收开头；只修最差的 3 个问题，只重渲改过的秒段。
6. **收尾沉淀记忆**：每期做完写日记；把用户本期的新纠正**原话带日期**补进制作记忆；补爆点库、零件清单、发布数据。纪律：多记原话、少写规则——原话能让执行方自己琢磨意图，规则堆多了只会照着做、发挥变差；当天新加的规矩若束缚发挥可当场撤。

## 提示词与模板

作者公开的 8 段提示词原文完整收录于 vault 笔记《一个人用 Claude Code 做知识视频：不用生成模型的代码渲染工作流笔记》，此处给结构索引：

1. 建工作台：目录清单＋CLAUDE.md 读取顺序＋「每类信息只写一处」＋每期收尾清单（日记、纠正原话入制作记忆、补三库）。
2. 建项目：竖屏 1080×1920/30fps；先测音乐生成 beats.json；一切时间从 beats.json 取；装依赖前先报备。
3. 拆爆款：ffmpeg 每秒抽帧拼联系表＋识别字幕与时间＋配乐速度与能量分析 →《拆解总览》七项（见步骤 1），数字标实测/估计，写完先给人看、不往下做。
4. 逐拍脚本（短版）：表格列 小节｜拍｜画面上发生什么｜屏幕大字｜小字；第 0 帧有字有画面；一屏一个重点；一句话拆 2–3 个词组落在拍上，最重要的词放重拍；大字 ≤6 字/秒；画面先变化再给名字。
5. 逐拍脚本（完整版）：约 17 秒内交出问题或反常识结果；过去的东西自动淡掉；每个例子写清「看得见的读数／看不见的变化／突变的那一刻」；音乐最空处放情绪低点、回满那拍放兑现；结尾回收开头物件、只放一种互动；有问题自己改好再交。
6. 写画面：先翻零件清单；每段先写六行（见步骤 3）；动作 0.15 秒到位；留平台安全区；不加免责小字。
7. 渲染前预审：每个画面事件抽静帧拼图自查叠字/挤/多重点，修完再渲染整段。
8. 审片：以「最挑剔的导演」身份按清单列问题与时间点，只修最差 3 个、只重渲改过的秒段、再交新联系表。
- 改片单格式：在哪（第 X 镜第 A–B 帧）／哪里不对／只改什么／哪些不能动（镜头运动、切点、字幕时间、其他镜头）／改完在 A、中间、B 三帧出静帧。

## 验收标准

- 拆解总览七项齐全，每个数字标了实测/估计；方向先经评论区高赞验证过，不凭感觉定题；
- 逐拍脚本：第 0 帧有字有画面，约 17 秒内问题出场；每个例子能独立证明主题；阅读时间检查跑过；
- 渲染前联系表过目：无叠字、无挤压、一屏一个重点；静帧先行，全片渲染次数 ≤2；
- 成片自查：无黑帧闪帧、无随机丢元素；屏幕上的数字逐一有出处或标示意；结尾回收开头物件；
- 收尾完成：日记已写、本期纠正原话带日期进制作记忆、零件与爆点库已补。

## 边界与风险

- 作者的开源仓库链接未随正文给出（自述在原帖评论区第一条，未能取到），「12 种画法」完整清单在仓库里、正文未列，本文件只收正文可核部分，不虚构清单内容；
- 全部效果与成本数字为作者自述，未独立核实：一期 128 秒用 Seedance 约 193 元/遍、抽 3 次约 580 元（作者自算，明说未做真实对照）；代码渲染同长度约 12 分半、0 元；2.5D 对照复刻 2 小时 15 分钟做完 58 秒片；互动比例 47%/32%/31% 为其拆解样本；
- 作者的对照发现对 2.5D 路线同样成立、属使用本法时要避开的坑：主角物件纯代码拼几何质量不可控（三版皆不像，只能改镜头绕开），真人感声音自动化不了——本法用「图解不用主角物件」绕开前者，声音仍需另行解决；
- 机器配音出戏是已知短板，作者后续靠剪映变声处理；Whisper 中文识别错字需逐字对稿，不可直接采信；
- 借对标的手法有明确边界：原句禁用清单是方法的一部分，照搬原话与选题越界。
