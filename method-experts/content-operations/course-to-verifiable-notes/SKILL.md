# 视频课转可查证学习笔记专家（专家模式）

- 领域：内容运营
- 来源：Haosen（@Haosen9527）长文《B站的课看完就忘？这 5 个 Skill，帮你整理学习资料》，收录于西瓜小本本第 305 条；vault 笔记《B站课程转学习笔记：五个 Skill 选型笔记》
- 核验状态：五个仓库经 GitHub API 逐仓核对，能力描述与仓库定位逐项吻合、星数已实测（见方法步骤）；作者明示只核对文档与关键脚本、未做安装与实测——选型框架与指令纪律可直接用，工具本体待验
- 适用：把 B 站（及同类）视频课从「看过就忘、找知识点要拖进度条」变成留得下、查得回、每条结论能核对原片的学习笔记

## 定位

这是一个「可查证优先」的学习资料整理者。它不相信总结代替原文：原始文字与整理解释永远分开存，重要结论必须留可核对的时间位置，存疑处列成回看清单而不是猜。工具上它不迷信全家桶，而是按需求环节选件——要截图文档、要字幕原文、要按词找课、要中文要点、要纯音频，各有各的件。它的工作纪律核心是一段给 Agent 的指令：先声明来源与覆盖，再动手整理。

## 何时用 / 何时不用

- 用：收藏了一批视频课，要沉淀成可检索、可查证的长期笔记；尤其有公式、板书、操作步骤的课。
- 不用：只想快速扫一眼某节课讲了啥（直接看即可，建档成本不划算）；或把机器字幕/转写当准确答案——专业词、数字、公式必须回原片核对。

## 方法步骤

1. **按环节选件**（五件均为 B 站 Skill，星数为收录时实测）：
   - 带截图、能编辑的文档 → **Video Notes**（asdhabdua/bilibili-video-notes-skill，54★）：下载视频与 AI 字幕、全覆盖抽帧、OCR＋感知哈希去重、视觉打分选截图，整理成 DOCX；适合有公式、课件、板书的课。注意 DOCX 模板单独跑不出笔记，要 Agent 编排填入。
   - 只留字幕原文查证 → **Subtitle Downloader**（DavinciEvans/bilibili-subtitle-download-skill，48★/MIT）：读 B 站现成字幕存为文本分块交 Agent 总结。注意其存稿**去掉时间戳**，精确定位要另存时间信息（见指令纪律的变通）。
   - 按关键词找课 → **Subtitle Fetcher**（suyuan2022/bilibili-subtitle-fetcher-skill，22★）：搜索＋字幕下载＋批量处理，输出带时间戳 Markdown。注意文档与源码不符（文档写 config.txt、脚本实际读 config.json），以源码为准、先小样验证；需 Cookie、无转写兜底。
   - 直接要中文笔记 → **Video Summary**（Roxy-ljy/bilibili-video-summary-skill，10★/MIT）：支持 B 站/b23.tv/YouTube，提取字幕后由 Agent 整理成中文 Markdown（摘要＋详细笔记＋要点）；无字幕时 faster-whisper 本地转写兜底（默认中文，外语课要改参数）。
   - 只想通勤重听 → **Audio Skill**（shuolsure/bilibili-audio-skill，5★）：底层 BBDown 提音频，支持单视频与按 UP 主批量；只出音频不出笔记。
2. **下指令**：把下方「给 Agent 的笔记指令」全文交给 Agent 执行，不临场改写纪律。
3. **先做一个短章节**：先处理一小节验证质量（来源声明、时间位置、存疑清单是否齐），合格再扩到整章；涉及付费模型调用先等确认。
4. **双份存檔**：原始字幕/转写与整理笔记分开保存——原文负责查证，笔记负责理解，永不混存。
5. **回看清单销项**：笔记里的存疑位置（公式、数字、术语）与待补截图处，回到原视频逐项核对后再定稿；图示、实验、板书不能只凭音轨确认。

## 提示词与模板

给 Agent 的笔记指令（全文，原文取自长文 article 的 MARKDOWN 实体）：

> 请根据这节课实际可获取的字幕或转写整理学习笔记。
> 先说明文字来源，以及覆盖了哪些分P或时间范围。
> 保存原始文字，再按知识点整理解释、条件和例子。
> 重要结论保留能核对的时间位置；拿不到时明确标注。
> 公式、数字和术语存疑时，列出需要回看原视频的位置。
> 涉及板书或图表的内容，标出需要补截图的地方。
> 最后给 3 个自测问题，不要只复述摘要。
> 不要仅凭视频标题补写内容。
> 本轮先处理一个短章节，涉及付费模型调用先等我确认。

指令纪律拆解（执行时逐条对照）：

- **先声明来源与覆盖范围**：文字来自现成字幕还是转写、覆盖哪些分 P 或时间段，开篇写明
- **原始文字与整理解释分开存**：原文一份、笔记一份，不互相污染
- **结论留可核对的时间位置**：每条重要结论带时间点；拿不到就明确标注「无时间位置」
- **存疑列回看清单**：公式、数字、术语拿不准的，列出需回看原视频的位置，不猜、不补
- **板书标补截图**：涉及板书或图表处标出待补截图位置（抽帧会漏短暂板书，更要标）
- **附 3 个自测问题**：检验理解，不只复述摘要
- **禁凭标题补写**：标题没讲到的内容一个字不编
- **先短章节、付费先确认**：小样验证在前，批量在后；付费模型调用先等用户确认

## 验收标准

- [ ] 笔记开篇已声明文字来源与覆盖范围（分 P / 时间段）
- [ ] 原始文字与整理笔记分开存放
- [ ] 重要结论均带可核对的时间位置，拿不到的已明确标注
- [ ] 公式、数字、术语存疑项已列回看清单，无一处凭猜填写
- [ ] 板书/图表内容已标出待补截图位置
- [ ] 文末附 3 个自测问题，且不是摘要复述
- [ ] 全文无仅凭标题补写的内容
- [ ] 本轮只处理了一个短章节先行验证；付费调用已事先确认

## 边界与风险

- 五个工具本体待验：作者明示未安装、未实测（只核对仓库文档、Skill 定义与关键脚本）；仓库都很小（5–54★），个别已逾一年未维护。框架与指令可直接用，工具跑不通时按环节换件，不要硬磕。
- 已知坑：Subtitle Downloader 存稿丢时间戳（与「结论留时间位置」的纪律冲突，使用时须另存时间信息）；Subtitle Fetcher 文档与源码不符，以源码为准；Video Notes 的视觉模型调用可能收费；机器字幕的专业词、数字、公式不能直接当准确答案。
- 平台纪律：随机等待不保证避免 B 站限流，下载工具不代替账号权限；批量处理前先确认账号可访问范围。
- 图示、实验、板书不能只凭音轨确认——音频转写路线（Video Summary 兜底、Audio Skill）产出的笔记，这类内容必须回看原片。
