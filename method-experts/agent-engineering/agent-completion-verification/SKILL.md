# Agent 完工验证闭环（专家模式）

- 领域：Agent 工程
- 来源：Codio（@0xCodio）虚幻引擎实测长文，基准为论文 CraftBench-UE，收录于西瓜小本本第 274 条；vault 笔记《Codio 虚幻引擎实测：C++ 对蓝图的 30 点差距笔记》
- 核验状态：基准数字与 arXiv 论文 CraftBench-UE 逐项一致（已核实）；论文评测的 7 个模型不含 Opus 5.5，原帖标题的 Opus 表述为作者体验口径；文中模型价格等为作者自述，未独立核实
- 适用：解决 Agent「存了文件、看了文件、从没按过运行」就宣布完工的问题——把完工定义从「产出存在」改成「实际运行验证过」

## 定位

这个专家来自一次大样本实测的行为发现：在 UE 5.8 官方 MCP 下跑 175 次任务，Agent 回读资产的占 85–94%、请求编译的约 75%，**真正启动运行验证的只有 22–25%**——通过率的差距大半不在生成质量，而在从没验证过。它把教训固化为三则纪律：完工定义前移、按「是否触发构建」分工、选格式按实测而非偏好。

背景数据（与论文逐项一致，已核实）：同等玩法任务，官方 MCP 下 C++ 通过 46/70、蓝图 25/70，**差 30 个百分点**；换第三方 MCP 差距拉大到 42.9 点；通过资产检查的蓝图作品里仍有 42%–50% 跑不通运行时断言；给 Agent 录像反馈是通过率最大单项改进（某模型 33.3% → 47.7%）。

## 何时用 / 何时不用

- 用：任何 Agent 产出可执行成果（代码、游戏逻辑、自动化流程、配置）的场合，尤其是「能保存/能编译」容易冒充「能运行」时；迭代成本高的环境（编译慢、构建重）更需要第二则的分工
- 不用：产出本身不可运行验证的纯文本任务（此时改用引用核查、独立路径复核等其他证据形式，第一则的「贴回结果原文」精神仍然适用）

## 方法步骤

### 第一则 · 完工定义前移

1. **资产保存 / 编译通过不算完工**：汇报完成前，必须实际运行本功能的测试，把结果摘要**原文贴回**回复
2. **零测试命中要明说**：没找到对应测试就停下声明，跑空一场不算证据
3. **无覆盖先写测试**：没有测试覆盖所求行为时，先写测试、先报测试名再报结果
4. 有条件时给 Agent **运行录像/录屏反馈**——实测中这是通过率最大的单项改进（33.3% → 47.7%，论文数据）

### 第二则 · 按「是否触发构建」分工

5. **需编译的改动攒批一次做**：原案例单文件重编译实测 89 秒且只吃单进程、堆硬件无用——逐个小改反复编译是纯浪费
6. **免编译面走快路径**：场景、配置、数据表、程序化图等不触发构建的改动即时做、即时验
7. **把热补丁边界写成系统提示词硬规则**：哪些改动可热补丁、哪些不可（原案例：反射类型不可），两类改动**绝不混在一次变更里**；任务两者都要时拆开，先做可补丁的一半

### 第三则 · 选格式按实测而非偏好

8. 同等功能优先放在**模型实测通过率高的文本格式**里（原案例：C++ 领先蓝图 30 个百分点）
9. 二进制格式只留给**人要亲自打开编辑**的部分
10. 判断标准不是「文本 vs 二进制」本身，而是**接口能否自描述并接受结构化输入**——程序化生成图是二进制资产，但官方给了含结构查询在内的 30 个工具函数，模型照样能用好

## 提示词与模板

原长文附注中藏有两段可直接复用的系统提示词规则（已取回，要点如下）：

**规则一（热重载分类）**：动手改 C++ 前先分类——普通函数/成员/类的函数体可自由改（可热补丁）；增删反射函数或属性、改类名或其规格、任何改变反射类型布局的改动不可热补丁，须停下让人关编辑器；两类改动绝不混在一次变更里，任务两者都要时拆开、先做可补丁的一半。

**规则二（完工定义）**：资产保存或代码编译通过不算完工——汇报完成前必须先发现并运行本功能的测试、把结果摘要原文贴回回复；零测试命中要明说并停下（跑空一场不算证据）；没有测试覆盖所求行为时，先写测试、先报测试名再报结果。

## 验收标准

- [ ] 每次「完成」汇报都附了实际运行的测试结果摘要原文，而非「已保存/已编译」
- [ ] 零测试命中的情况被明确声明，没有用空跑冒充证据
- [ ] 新增行为在无覆盖时先补了测试，且先报测试名再报结果
- [ ] 需编译的改动是攒批做的，没有逐个小改反复触发构建
- [ ] 可热补丁与不可热补丁的改动没有混在同一次变更里
- [ ] 格式选型有实测依据；二进制格式的使用都对应「人要亲自打开编辑」的明确理由

## 边界与风险

- 原案例环境是 UE 5.8 官方 MCP，其能力边界（不能编译/构建/触发热重载、无鉴权层不可暴露到本机之外、工具串行、新增工具须重启编辑器）是该环境的事实，迁移到其他工具链时要重新盘点
- 30 / 42.9 个百分点、C++ 46/70 对蓝图 25/70 等数字来自 CraftBench-UE（70 任务、7 模型、确定性检查、无模型当裁判），已与论文核对一致；但这是该基准的结论，不是对所有任务类型的普适定律
