# 长程多 Agent 运行时机制（专家模式）

- 领域：Agent 工程
- 来源：N1nEmAn/sapper-v2（开源多智能体渗透系统），经何笠聊 AI（@HeLi8866）帖介绍，收录于西瓜小本本第 314 条；vault 笔记《SAPPER：多智能体全自动渗透红队笔记》
- 核验状态：仓库 1,101★ / 679 forks / MIT、架构与机制件经仓库 README 逐项核对属实（2026-11-05）；比赛成绩（腾讯云智能攻防挑战赛冠军、634 支队伍、8 小时无人值守、GeekCon 2026 一等奖）、85 flag 与 1B vs 4.5B tokens、260K 轮换阈值均为项目自述，未经第三方核实
- 适用：要让一群 Agent 无人盯着跑数小时的长程任务（研究、工程、监控、竞赛）时，提供原则之下的运行时机制件——与 [Loops & Graphs 编排法](../loops-and-graphs/SKILL.md) 互补：彼给编排原则（检查先行、证据分级、失败处置），此给运行时（共享记忆、条令、保活、轮换）

## 定位

地基只给三能力，细则让组织自己长：Create（拉起新 agent）、Language（agent 之间发话）、History（一张所有人共享的事实-意图图）。指挥官只读棋盘、判断、派发，从不亲自执行；可靠性不靠模型自觉，靠纯脚本看门狗；经验不随个体死亡丢失，写进图和 playbook 传给继任者。

## 何时用 / 何时不用

- 用：多 Agent、长时运行（小时级）、执行者会崩溃/饱和/被回收是常态的任务；需要成本可控（模型分层）的批量并行工作
- 不用：单 Agent 短任务（机制件全是 overhead）；无法定义「事实」与「证据」的开放创作（事实-意图图会退化成闲聊记录）
- 安全边界：原项目是双用途渗透工具，仅限有授权的实验环境与 CTF；本专家模式只取其编排机制，迁移到其他领域时用通用底座（原作者的 nvwabase）思路，不带攻击条令

## 方法步骤

1. **搭三能力地基**：Create——用 tmux 等方式以脚本拉起新 agent 会话；Language——agent 之间往对方输入框发话（不用复杂协议）；History——建一张共享的**分层事实-意图图**：每条事实三层存储（标题→摘要→证据文档），读者按需下钻，防单条坏事实污染全图、防上下文空烧。
2. **设指挥官**：只读图、判断、派发，自己永不执行；调度纪律全部写死在一份条令文件里（原项目是 426 行的 commander SKILL.md），条文包括：易者先行并行调度、瓶颈时间抢救半解目标、止损纪律。**条令即代码**——改行为先改条令，不靠临场叮嘱。
3. **分层用模型**：决策层（指挥官/将军）用强模型，量产层（士兵/侦察）用轻模型；成本由组织结构决定，不由单模型价格决定（原项目自述：同等产出下 1B tokens 对对手 4.5B）。
4. **上零策略看门狗**：纯脚本负责保活——崩溃自动带 `--continue` 重启、配额耗尽轮换 key、到时强制收尾。看门狗不做任何策略判断，不占模型。
5. **轮换与继承**：执行者上下文接近饱和（原项目自述实测约 260K）即回收；回收前把经验写成 playbook 留给继任者。原则：个体可死，图与经验存活。
6. **内置领域知识库**：把领域知识做成离线 KB 供执行者查（原项目是渗透知识库），与事实图分离——KB 是「怎么做」的先验，图是「现在什么情况」的事实。

## 提示词与模板

无单条提示词模板；核心工件是两份文件：一份**指挥官条令**（调度规则全集，写成可执行的纪律条文）与一张**事实-意图图**（三层：标题/摘要/证据文档）。搭新系统时先写这两件，再写单个 agent 的提示词。

## 验收标准

- 指挥官全程没有亲自执行过任何一步（只读图、只派发）——查其会话记录。
- 任意杀掉一个执行者，任务能靠图＋playbook 在继任者手里续上，不丢已确认事实。
- 看门狗演练过：手动杀进程、耗尽一个 key，系统能自愈并继续。
- 成本核算分层列出（决策层 vs 量产层 token 量），与单模型方案对比有据。
- 条令文件是行为的唯一出处：任何调度行为都能在条令里找到对应条文。

## 边界与风险

- 比赛成绩与全部效果数字为项目自述、未第三方核实，不得当作已证能力引用。
- 仓库仅 6 天（2026-10-30 建仓），机制设计可借，代码成熟度待观察。
- 「涌现的组织发明」（信号员、绩效面谈等）是项目自述的展示样本，不是可复现的保证。
- 原项目为双用途攻击工具：仅限授权环境/CTF；把机制迁到其他领域时，不连带迁移攻击条令与知识库。
