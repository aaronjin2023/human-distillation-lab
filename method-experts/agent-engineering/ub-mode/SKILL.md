# ub-mode 代码整洁门禁（专家模式）

- 领域：Agent 工程
- 来源：Robert C. Martin（Uncle Bob）的开源 Skill `unclebob/ub-mode`，龙海（@longhaiqwe123）拆解长文（Kin 转发），收录于西瓜小本本第 58 条；vault 笔记《ub-mode：Uncle Bob 给编程 Agent 的代码整洁之道笔记》
- 核验状态：仓库真实性与星数已核实（收录时 3,155★，核心 SKILL.md 152 行）；作者的实测重构效果为作者自述，未独立核实；**本机状态：已实际启用**——2026-10-28 经用户批准装给本机 pi（磨牙棒），SKILL.md 在 `~/.pi/agent/skills/ub-mode/`，`~/.pi/agent/AGENTS.md` 已写入默认规范指令，冒烟测试通过（pi 自述默认标准为 ub-mode）；三大门禁工具源码克隆在 `~/workspace/tools/ub-gates/`，启动器首次运行自动建 venv
- 适用：让编程 Agent 写代码时自带整洁纪律与量化交付门禁，解决「AI 写的代码越来越冗余、越改越乱」

## 定位

这是 Uncle Bob 把《代码整洁之道》的工程思想写成的一份给编程 Agent 用的 Skill：整个仓库就两个文件，核心是一份 152 行的 SKILL.md，放进技能目录即可调用。主线是他那句老话——先让功能可用（First Make it Work），再把代码写好（Then Make it Right），最后按实践交付（Follow Practice）。它不信「看起来没问题」，交付必须拿出可量化的门禁数据。

## 何时用 / 何时不用

- 用：任何让编程 Agent 写/改代码的场合，尤其是多轮迭代、容易越改越臃肿的代码库；修 bug、重构、加新功能都适用
- 不用：一次性脚本且明确不需要维护时可放宽门禁（但实现纪律仍建议守）；门禁工具仅支持 Clojure/Java/Go/TS/Rust/Python，其他语言只能守实现纪律、无法跑量化门禁

## 方法步骤

### 第一层 · 实现纪律

1. **一个决定只住一处**：同一个业务判断在全库只能存在于一处（One decision lives in one place）；永远交能解决问题的最小改动
2. **先定数据结构再写逻辑**：动手写分支逻辑前先定 Data Shape；用类型系统让非法状态无法表达（判别联合代替散装布尔/可选字段）
3. **边界校验一次**：外部数据只在系统边界解析校验一次，内部直接信任；核心逻辑用纯函数；操作要幂等；共享可变状态必须单一写入者；不许屏蔽编译器警告
4. **诚实 TDD**：先写失败的测试 → 确认它因预期原因失败 → 写最小实现；**写不出诚实的测试就不许写假测试充数**
5. **不往旧设计上硬 bolt**：新需求从第一性原理重推；先删后加；重复性活先手工做一个标准件，再写工具放大
6. **连续两次修复失败就停**：先用一句话写出两次失败的共同前提并质疑它（Attack the Premise），再动手

### 第二层 · 量化门禁（交付前必跑，拿出数据）

7. **crapper**：算每函数的 CRAP 分 = 圈复杂度² × (1−覆盖率)³ + 圈复杂度，要求 **< 10**（调用传 `--threshold 9.99`）。注意：复杂度到 10 时哪怕覆盖率 100% 也刚好等于 10，超标只能拆函数、不能只补测试
8. **dryer**：用归一化 AST 指纹的 Jaccard 相似度查结构性复制粘贴，清掉相似度 **≥ 0.8** 的块（`--threshold 0.8`）
9. **mutator**：做变异测试（把 `>=` 换成 `>`、`+` 换成 `−` 之类）；测试还全过 = 变异体存活 = 测试有盲区（经典例：满 100 免运费只测了 50 和 150，行覆盖 100% 也抓不到边界）。处理要求：补未覆盖测试、补边界断言杀掉存活体、删死代码；存活时退出码 3
10. **修 bug 纪律**：只加个判空把崩溃藏起来不算修复，要找根因；测试按外部行为写——函数全返回空测试还过的测试直接删
11. （可选）uml-viewer 把指标叠到架构图上看健康度（仓库 README 推荐，未写进 Skill 本体）

### 第三层 · 工程习惯

12. 记操作日志并汇报摘要；守上下文窗口（大输出分流到文件/子任务）
13. 清理 worktree 时，未提交的改动必须停手问人，不擅自清理
14. 小步提交，commit 信息写清 Why / What / 证据

## 提示词与模板

无固定提示词模板。执行方式是把 ub-mode 的 SKILL.md 装进编程 Agent 的技能目录并设为默认规范（本机 pi 已如此启用），写/改代码前先读该 Skill，按「实现纪律 → 量化门禁 → 工程习惯」三层执行。

## 验收标准

- [ ] 同一业务判断全库只有一处实现；交付的是最小改动
- [ ] 外部数据只在边界校验一次；核心逻辑为纯函数；共享可变状态单一写入者
- [ ] 新代码有先失败后通过的诚实测试；没有假测试充数
- [ ] crapper：每函数 CRAP < 10（阈值 9.99）
- [ ] dryer：无相似度 ≥ 0.8 的结构重复块
- [ ] mutator：无存活变异体（退出码非 3）
- [ ] 修 bug 给出了根因，而非判空藏崩溃；按外部行为写的测试无「全返回空还过」的
- [ ] 未提交改动未被擅自清理；提交信息含 Why / What / 证据

## 边界与风险

- 门禁工具支持语言有限（Clojure/Java/Go/TS/Rust/Python）；其他语言无法跑第二层量化门禁
- 作者在自己开源项目上的实测结论（存活变异体集中在边界判断、补断言＋拆纯函数后复检达标）为作者自述，未独立核实
- 「复杂度 10 时满覆盖也达标不了」是公式的必然结果，不是经验之谈——遇到 CRAP 超标先拆函数，不要试图用补测试过关
