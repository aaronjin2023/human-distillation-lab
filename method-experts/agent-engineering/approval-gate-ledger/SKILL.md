# 审批门 + 账本去重（专家模式）

- 领域：Agent 工程
- 来源：Whisper（@Whisperrrrr66）《Muse 全自动找工保姆级教程》，收录于西瓜小本本第 164 条；vault 笔记《Muse 全自动找工流水线笔记》
- 核验状态：岗位源仓库 SimplifyJobs/New-Grad-Positions 已核实真实存在（收录时 18,307★、每日更新属实、license 字段为空）；整套流程的自动化率「90%+」为作者自述，未独立核实
- 适用：让 Agent 跑一条完整的批量业务流水线（筛选 → 执行 → 提交），同时用审批门防失控、用账本防重复、用状态禁区防误伤——投简历只是原案例的载体，方法可迁移到任何批量提交型任务

## 定位

这个专家把「让 Agent 端到端跑业务流」拆成五件可迁移的设计：先喂档案、审批门、Ledger 账本、状态感知禁区、模糊放行明拒才拦。它的清醒之处在于目标不是 100% 自动化，而是把人工压缩到只剩审批和机器过不了的验证环节（约 90%，作者自述，未独立核实），其余全部交给机器批量跑。

## 何时用 / 何时不用

- 用：批量、重复、对象明确的提交型流水线——批量投递、批量投稿、批量提交表单、逐站提交等，每单流程相同、需要跨批次防重复的场合
- 不用：单件任务（没有批量和去重问题，审批门只会拖慢）；不可逆且后果重大的操作（审批门拦的是「执行前」，拦不住执行本身的后果，这类任务另设更严的人工流程）；对象状态无法可靠查询时（状态禁区会失真）

## 方法步骤

1. **先喂档案**：把个人信息与高频问答（原案例：常见投递问题的答案）预先结构化给 Agent，省去每单重复确认；Agent 筛选和填写时直接查档案
2. **喂入对象清单**：给出本批待处理对象（原案例：每日自动更新的岗位清单仓库 SimplifyJobs/New-Grad-Positions），Agent 逐个打开详情核对
3. **机器初筛**：按硬条件过滤（原案例：毕业时间/经验是否符合、岗位是否还开放、是否要求 citizenship / clearance）
4. **审批门**：机器先把筛完的清单发人确认，人回 `approved` 才开始执行；信任建立后可切换为全自动，但默认从带审批门起步
5. **执行并适配**：按对象微调材料再提交（原案例：按 JD 选 SDE / AI 简历模板、微调后重新编译成 1 页 PDF、自动填表、答开放题、上传提交）
6. **Ledger 账本回写**：每次提交成功立刻写进已处理清单（原案例可绑定 Gmail 让 Agent 自行整理已投岗位进账本），下一批先查账本去重，绝不重复提交
7. **状态感知禁区**：已进入后续阶段的对象列入禁区名单，Agent 禁止再碰（原案例：已进入 recruiter / interview / OA 的公司禁投）
8. **模糊放行、明拒才拦**：条件不确定就放行，只有明确写明不符合才过滤（原案例：sponsor 没写明可以投，明确 no sponsorship 才过滤；citizenship / clearance 不符合直接过滤）——目的是减少误杀
9. **凭据纪律**：批量任务给临时账号密码，一批一换、用完即弃，不长期保存（原案例针对 Workday 每家公司都要重新注册账号的问题）
10. **人工兜底项事先声明**：CAPTCHA、邮箱/短信验证码、严格身份验证、电子签名留人工介入，不硬闯

## 提示词与模板

无固定提示词模板，按方法步骤执行。关键的两个结构件是：

- 审批门消息：机器发「筛选后清单」→ 人回 `approved` → 才执行（可配置为全自动）
- Ledger 账本：一对象一行，字段至少含对象标识、处理时间、结果；每批开工前先与账本比对去重，成功后立即回写

## 验收标准

- [ ] 档案已预结构化，Agent 执行中没有反复回头问高频问题
- [ ] 每批执行前都经过审批门（或已明确切换为全自动并记录在案）
- [ ] 每单成功后都已写回 Ledger；抽查账本与实际提交记录一致
- [ ] 跨批次无重复提交（用账本比对验证）
- [ ] 状态禁区名单生效：已进入后续阶段的对象未被再次处理
- [ ] 过滤决定符合「明拒才拦」：不确定项被放行而非误杀
- [ ] 临时凭据已在本批结束后弃用，未长期保存
- [ ] CAPTCHA/验证码/电子签名等兜底项都走了人工，没有硬闯或绕过

## 边界与风险

- 自动化率「90%+」为作者自述，未独立核实；实际比例取决于目标站点的验证强度
- 把账号密码交给 Agent 即便临时也有风险，「用完即弃」是必要缓解、不是万全
- 原案例是北美应届求职语境（sponsorship / citizenship / Workday），迁移到其他业务时要重设筛选条件与禁区状态定义
- 岗位源仓库 license 字段为空，引用其数据时注意
- 审批门切换全自动前，应先在小批量上验证账本与禁区的可靠性
