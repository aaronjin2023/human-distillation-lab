# Godot 回合制 RPG 结构法（专家模式）

- 领域：游戏开发
- 来源：GDQuest 团队开源项目 godot-open-rpg（gdquest-demos/godot-open-rpg，MIT），项目自述目标即「演示如何为 Godot 4 的 2D 回合制 RPG 组织代码结构」；西瓜逐文件核读其 78 个 GDScript 源码后提炼，收录于西瓜小本本第 427 条；vault 笔记《Godot Open RPG：回合制 RPG 结构范例笔记》
- 核验状态：仓库结构与关键源码（BattlerAction / BattlerStats / CombatEvents / Inventory / Interaction）已逐文件核读；3,052★ 为 GitHub API 核；项目自述为开发中（WIP，需 Godot 4.7.2+），未本地实跑
- 适用：在 Godot 4 里从零搭一个回合制 RPG（或其他「探索 + 战斗」双状态游戏）的项目骨架；给编码 Agent 下结构约束时同样适用

## 定位

RPG 项目最容易烂尾的不是某个系统写不出来，而是系统之间互相缠绕：战斗代码伸进地图、UI 直接改数值、交互逻辑散落在每张地图里。本法是 GDQuest 教师团队的范例答案：先按「游戏状态」切域，再把战斗拆成数据与动作类，把地图交互统一成一种可模板化的对象——每个系统都只通过窄接口与外界说话。

## 何时用 / 何时不用

- 用：Godot 4 的 2D 回合制 RPG 立项与骨架搭建；已有项目开始缠绕时的重构参照；让 Agent 生成 RPG 代码时先把此结构定为约束
- 不用：动作/实时战斗为主的游戏（回合与就绪度模型不适用）；一次性 jam 小品（结构成本收不回来）

## 方法步骤

1. **按状态切三域**：代码分 `combat`（战斗域）、`field`（大地图探索域）、`common`（两域共享：背包、玩家、音乐、转场、方向、碰撞）。内容目录照代码域镜像摆放（arenas / battlers/<生物> / maps/<地图>），找任何东西先问「它属于哪个状态」。
2. **战斗 UI 独立成域**：战斗界面（动作菜单、战斗者条目、光标、特效标签）全部收进 combat 下的 ui 子域，只读状态、发意图，不直接改数值。
3. **技能 = 数据资源 + 动作类**：定义抽象类 `BattlerAction extends Resource`，技能在编辑器里配成数据文件：目标范围枚举（SELF / SINGLE / ALL）、友敌标志、属性、能量消耗；子类只实现具体效果（攻击、治疗、改属性、投射物）。新技能 = 新数据文件或新子类，不动战斗主循环。
4. **就绪度回合制**：回合推进按速度与 readiness（就绪度）运转；动作带 `readiness_saved` 字段——行动后保留多少就绪度，弱攻击可靠它换取更快再动。把「行动经济」做进数据，而不是写死在流程里。
5. **执行协议固定**：动作先过 `can_execute()`（来源存活、能量足够等校验），再由 `execute()` 协程包办逻辑与动画；目标缓存在动作对象上，命中结算独立成对象（BattlerHit），不散落在各技能里。
6. **属性 = 带信号的资源**：`BattlerStats extends Resource`：基础值用 setter 触发派生值重算，可被修正的属性集中成一张清单（MODIFIABLE_STATS 式），血量/能量变化与耗尽全部发信号——UI 与逻辑靠信号解耦。
7. **域间只走事件总线**：战斗与外界只经一个信号总线节点（如 CombatEvents：combat_initiated / combat_finished / player_battler_selected）通信；战斗本身是一个可切换的游戏状态，由转场（ScreenTransition 自动加载）盖屏进出，地图代码不直接调用战斗内部。
8. **地图交互 = 一切皆小剧情**：`Interaction extends Cutscene`：交互就是可被触发的小剧情，由玩家位置与朝向格触发（is_active 开关）；把高频类型沉淀为模板——区域切换、战斗触发（含游走触发）、对话、门、拾取、宝箱，新地图拼模板，不重写逻辑。
9. **现成轮子不自造**：对话用 Dialogic 插件的时间线系统接入本结构，不自研对话引擎；网格移动由 Gameboard + 带控制器（含光标控制器）的 GamePiece 承担。
10. **状态用资源落盘**：背包等全局状态做成单个 Resource 存入 user://（如 inventory.tres），配静态 restore() 负责读盘、缺失则新建——随时可取，不依赖某个场景节点存活。

## 验收标准

- 任何文件都能按「所属状态域」归位；combat 与 field 之间没有直接互相引用，只经 common 与事件总线
- 新增一个技能不需要改战斗主循环；新增一种地图交互优先落在已有模板上
- UI 层不直接写数值：所有状态变化经资源 setter 与信号传播
- 关掉战斗域，探索域可独立运行；反之亦然

## 边界与风险
